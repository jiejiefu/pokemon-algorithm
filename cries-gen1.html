寶可夢演算法

選擇寶可夢

依 base cry 分組

38 個 base cry 共用於 151 隻。同一組內的叫聲只差在音高與長度兩個位元組上。

這裡的音訊是瀏覽器即時合成的，不是錄音。要聽原始錄音請看 叫聲總覽。

第一世代叫聲實驗室

紅／綠／藍的 151 隻，並不是各自擁有 151 段不同的叫聲錄音。當時受限於 Game Boy 卡帶極為有限的儲存空間，為了極大化節省音效容量，Game Freak 僅製作了 38 段基礎叫聲（Base Cries），其餘叫聲全是以這 38 段為原型改寫而來。

改寫只靠兩個位元組：Pitch（0–255）會直接加到旋律的頻率值上 —— 不是改變調，而是把數字加上去，所以加過頭會超出暫存器而捲回低頻；Length（−128…127）則是時間縮放乘數，決定這段旋律播多快。同一段 base 配上不同的兩個位元組，就是一隻寶可夢的叫聲。

這一頁用瀏覽器的 Web Audio 重新合成全部 151 隻：拉動那兩個滑桿，就能立刻聽到「同一段旋律、不同兩個位元組」是什麼感覺，也能量出哪些寶可夢其實聽起來一模一樣。

合成與聲道

混音與逐聲道波形

四條軌道共用同一段時間軸、同樣寬度、同樣的左緣：最上面是三條聲道混在一起的結果，下面三條是各自的波形，每條波形下方是它的音符區段。指令表裡的幀數是儲存值 + 1（原始位元組存的是「幀數減一」，所以 $3 是 4 幀、$F 是 16 幀），而軌道上的長度已經套用長度位元組的時間縮放，兩者不一定相同。

三條聲道各跑各的：脈衝聲道的音符結束於自己的幀數，噪音聲道比較長時，它最後那段會在脈衝聲道結束之後繼續 —— 而那正是音高偏移已被取消的地方，也是那條軌道尾端突然變平的原因。靜音某一條只改變混音，不改變它自己的波形，所以那條軌道會變灰但不會消失。

這張表裡能算出來的東西

兩組完全相同的叫聲

噴火龍與獨角犀牛、蚊香蝌蚪與百變怪，base cry、音高、長度三個值完全相同 —— 合成出來的 PCM 是位元組相同的。

注意：獨角犀牛（Rhyhorn, #111）和鑽角犀獸（Rhyhon, #112）是兩隻不同的寶可夢。後者用的是 base 11，只和前者在音高與長度上相同、基底不同。中文資料常把這兩個名字混用，導致「噴火龍和鑽角犀獸同叫聲」的錯誤說法。

兩組幾乎相同的叫聲

綠毛蟲與角金魚共用 base 22，長度位元組分別是 0x20 與 0x40。第一脈衝聲道的長度因此差 —，Bulbapedia 記載為 0.071 秒。

腕力與菊石獸共用 base 31，音高分別是 0xEE 與 0xF0，頻率相差 —。

差異比想像中小：0.071 秒的長度差要靠 Bulbapedia 的數字才量得出來，音高差不到 1%。

音高偏移會把音符捲繞回最低頻

頻率暫存器只有 11 位元，音高是直接加上去的，超過 2047 就捲回接近 0。

蚊香蝌蚪與百變怪共享 base 0E，音高是 255（最大值），於是第一個音符落在 131,072 Hz —— 那不是聲音，是聽不到的超高頻。往後三個音符都溢出，各自捲到 66–510 Hz，結果是一聲低沉的轟鳴。

這個捲繞不是模擬的缺陷，而是文件記載的行為：較大的偏移可能讓結果比原音更低。當前選擇的物種有 — 個音符會捲繞。

為什麼有些叫聲尾巴會「崩潰」

噪音聲道的音高偏移，在兩個脈衝聲道排定結束前一幀被清除，而硬體並不檢查噪音聲道的狀態。所以噪音聲道裡在那一刻之後才開始的音符，整個都用原始參數播放，不帶偏移 —— 偏移不是被「撤銷」，而是從來沒加上去。於是相鄰兩音符之間出現一個音高跳躍，那就是崩潰。

要留意的是「排定」：這是各音符幀數的總和，不是實際渲染出來的長度。ring-out 會讓脈衝聲道實際跑得比排定的久，若拿渲染長度當基準，取消的時點就會被推遲。這份資料庫裡沒有任何一個噪音音符跨越那個界線，所以崩潰一律發生在音符與音符之間，而不是某個音符唱到一半轉調。當前選擇：—

151 隻、38 段、重製之後

第七世代之後每一隻都有自己專屬的叫聲，第一世代這種「同一段音樂反覆變調變速」的做法就消失了。這也是為什麼 Bulbapedia 說那些曾經相同的叫聲，現在已經不再相似。

對照：第二世代把基底擴充到 68 段，其中 30 段是新的，只有耿鬼與月亮伊布沿用第一世代的基底。

這一頁是怎麼合成的

Game Boy 的 CPU 跑在 1,048,576 Hz，這裡以 65,536 Hz 合成 —— 剛好是 1/16，沒有任何誤差，一個 59.7275 Hz 的音符幀正好 1090.67 個樣本。Web Audio 的取樣率上限是 96,000 Hz，所以無法直接用真實時脈。

代價是 32.768 kHz 以上的頻率全部遺失。Game Boy 的脈衝波是方波，方波的諧波延伸到無限遠，所以高頻噪聲會和真機有一點差異 —— 參考作者本人的網頁也標註了同一件事。音量包絡的每幀步進速率不在兩份上游說明裡，是模型而非實測，頁面控制台可調整。

出處

指令與數值來自 pret/pokered 的 data/pokemon/cries.asm 與 audio/sfx/。分組與相同叫聲的說法對照 Bulbapedia 的 Cry 頁，音訊格式的細節來自該頁引用的技術說明。

這一頁的合成器重新推導自 rgmechex 的 Generation I Cry Synthesizer，以下行為以它的實作為準：方波 duty 暫存器每幀旋轉一次、Volume envelope 只在每 |sweep| 幀步進一次而不是連續衰減、噪音通道不吃長度位元組的時間縮放、噪音率同時用到參數的兩個欄位、最後一個音符會響到包絡歸零而不是在 sound_ret 處硬切。特別感謝這份網頁的作者。
