## F. Cry Audio & the Generation I Table
Two independent sources, two independent sets of traps. Neither may be hand-edited; both are generated and both are checked.

**`assets/js/cry-index.js` (generated by `scripts/extract_cry_index.py`)** rosters `assets/cries/`, a byte-for-byte copy of [PokeAPI/cries](https://github.com/PokeAPI/cries). No re-encode, no rename — what plays is exactly what played when the page fetched it from `raw.githubusercontent.com`.

- `latest/` holds 1,351 files and covers all 1,025 species; the 326 unclaimed `10000+` form files are counted and reported but kept out of the roster, on the same rule as §3.E. `legacy/` holds 649 files, the older Gen 1-5 recordings.
- **93 files under `latest/` are not Ogg despite the extension** — 92 are MPEG layer III and one is a WAV. Only ids **25, 808, 809** are roster species; the other 90 are form files. So `Content-Type: audio/ogg` on `25.ogg` is a lie the browser never sees: `decodeAudioData` sniffs content rather than trusting the header, and `canPlayType` cannot be trusted to detect them at all. The checker magic-sniffs all 1,674 roster files rather than reading extensions.
- **Every legacy file differs from its latest counterpart — 649 of 649, byte for byte.** "Old recording" is the entire reason `legacy/` exists; a copy backfill would silently retire it, so the checker compares all 649 pairs.
- **Peaks exceed 1.0.** `25.ogg` decodes to a maximum sample of 1.0391, so any envelope built by sampling raw float data must clamp or it draws outside the canvas.
- `node scripts/check_cry_index.mjs` (50 checks) and `node scripts/test_check_cry_index.mjs` (21 mutation cases) guard it. Four of those cases failed when first written and each was a real hole, not a bad expectation — worth reading before trusting any assertion here that "looks obviously true".

**`assets/data/gen1_cries.json` + `gen1_cry_sfx.json` (generated by `scripts/fetch_gen1_cries.py`)** parse [pret/pokered](https://github.com/pret/pokered)'s `data/pokemon/cries.asm` and 114 `audio/sfx/cry{NN}_{1,2,3}.asm`. The `.asm` files are **build-time inputs and are not vendored**; they mirror into the gitignored `data-sources/pokered-cry/` when `test_check_gen1_cries.mjs` needs them.

- **The table is unordered from its first row.** All 151 species sit at a position that is not their dex id, by up to 174 places; row 1 is Rhyhon (id 112). So every id in the JSON can only have come from the `; Name` comment — a positional join would hand Bulbasaur Rhyhon's cry. `test_check_gen1_cries.mjs` **shuffles the rows and requires the regenerated JSON to be byte-identical**, which is the only thing that actually proves it; a comment cannot.
- **The join key has two hazards in it.** Punctuation differs (`Mr.Mime` upstream, `Mr. Mime` in `pokemon_data.json`), so punctuation is dropped; but Nidoran♀ (29) and Nidoran♂ (32) differ *only* by a gender symbol, so symbols are transliterated (`♀`→`f`, `♂`→`m`) rather than dropped. Getting either backwards merges two species onto one key, which is why an ambiguous key is a hard error and never a coin flip.
- **38 base cries, not 114 files.** Upstream ships each base three times as three link entries for one sound; the copies carry identical commands and differ only in the `_1`/`_2`/`_3` inside their labels — including inside cry0d's `sound_loop` target, which is why loop targets are stored as `"Ch5"` and not as literal labels. The fetcher stops the build if the replicas ever diverge, and `check_gen1_cries.mjs` re-asserts it.
- **Case is the whole filename trap.** Constants are uppercase hex (`SFX_CRY_1A`), filenames are lowercase (`cry1a_1.asm`). A case-sloppy map looks right for the ten all-digit bases and 404s for the other twenty-eight.
- **Upstream is not self-consistent, and the checker must not be.** `cry02_1.asm` uses the older single-value `duty_cycle` (expanded to four repeats on parse); the volume sweep is a signed nibble written both ways (`noise_note 13, 1, -1, 124`); `cry06_1.asm`'s Ch6 is an empty channel; and **six** of the 114 channels have no `sound_ret` at all — recorded in `implicitRet` and asserted as an exact set, because "at most six" would pass both when the parser drops commands and when upstream fixes one. Never assert something upstream does not do.
- `node scripts/check_gen1_cries.mjs` (40 checks) and `node scripts/test_check_gen1_cries.mjs` (23 mutation cases plus the shuffle proof) guard it.

**`assets/js/gb-apu.js`** re-synthesises those 38 base cries, so `cries-gen1.html` plays the cries rather than loading them. It is a pure module with no DOM, no Web Audio and no fetch, which is the only reason the claims below are checkable at all.

**It is verified against the reference's own OUTPUT, not against a description of it.** `assets/data/gen1_conformance.json` holds, for all 151 species, the output length plus 48 sampled values of the 8-bit form the reference page's Download button produces — generated by driving that page in headless Chrome, not by reading its source. The checker also re-imports the APU at 1,048,576 Hz to produce those renders, since Web Audio's ceiling is why the page uses 65,536.

*This distinction is the single most important thing in this section.* Six bugs had this APU confidently disagreeing with the reference while **agreeing with every other file in the project**, because every assertion compared it to a *description* — and a description can be wrong in ways that are self-consistent. Nothing short of comparing output found any of them. Current result: all 151 lengths match exactly, 98.7% of sampled values are byte-identical, every remaining one within one 8-bit step.

**The comparison is 48 samples per species, and that is deliberate.** It used to be 48 samples plus one full-file byte-compare: `assets/data/gen1_charizard_ref.raw`, the reference's complete 1,000,692-byte download for #006. Nothing read it. `check_gen1_apu.mjs` only ever opened the three JSON tables, `gb-apu.js` and `cries-gen1.html`, so the file was copied into all 36 mutation fixtures — about 36 MB of pointless I/O — while AGENTS.md described a byte comparison that had not existed for some time. That is the §4 failure shape exactly: a claim nothing was checking, written down so precisely that it read as verified. The file is gone; the 151 × 48 comparison is what runs, and what the numbers above describe. Regenerating a whole-file vector would mean a 1 MB tracked artifact per species change, which is the cost the sampled form exists to avoid.

- **The length parameter is the stored byte MINUS `0x80`, not its two's-complement signed reading.** The reference's slider holds `byte - 0x80` and the multiplier is `+0x100`. Reading the byte as signed gives a multiplier `0x80` larger, which makes every note **1.5× too long**. Charizard stores `0x80`, so its parameter is `0` and its multiplier `0x100` — no stretch at all; the byte-as-signed reading makes it `0x180`. Its sampled vector settles it: the lengths stop matching.
- **The duty register holds the PACKED byte, not the pattern array.** The reference reads it as `duty & 3`, so an array coerces to `NaN` and then to `0` — silently selecting the 12.5% window on every note of every channel whose low two bits are not `00`. Charizard's second pulse channel is duty `$5A`, low bits `2`, so that channel played inverted for the entire cry. The two channels whose low bits happened to be `0` matched by luck, which is what made this look like tuning rather than a bug.
- **The mix is NOT peak-normalised.** Three channels at a third each sum to at most 1.0, so the signal cannot clip; normalising only rescaled every cry, made a soloed channel as loud as a full one, and made comparison against the reference impossible.
- **Every register is in samples at the Game Boy's clock, so each must be scaled to the output rate — including the noise LFSR clock, which was not.** The pulse channel's `period` was; the noise channel's was not, so at 65,536 Hz the LFSR ran once per 512 *output* samples: 128 Hz where the hardware means 2,048. The symptom was a cry that was correct in every respect except that it had **no hiss in it**. Measured on the rendered channel, 76 zero crossings per second against the reference's 1,533; after the fix, 1,532.
- **…and that is precisely what a native-rate conformance comparison is blind to.** At 1,048,576 Hz the conversion factor is exactly 1 and the bug is a no-op. Comparing at the native rate is what makes every length and every waveform sample verifiable, and it is exactly the rate at which a rate-dependent bug disappears. So the checks for it are **rate-independent by construction**: the same species must report the same noise clocks and render the same grain at 65,536 and at 1,048,576. Expect this shape again — a quantity that only matters on the way to the speakers can only be checked on the way to the speakers. The master volume was the other one, and **it has been removed rather than checked**: `sliderToMaster()` mapped a 0..10 page slider onto the channel scale's 0..15, which made the default reading of 3 a master volume of 5 — a third of full scale, too loud — and it was a conversion between two numbers that were already the same unit, so there was nothing for it to be right about. The page now presents 0..15 directly and defaults to 3, and the claim is asserted **by measuring** rather than by reading an expression, because it is still the one loudness quantity no waveform assertion can reach.
- **The duty register turns once per FRAME** (upstream's own comment says "once per frame"), and the volume envelope steps once per `|sweep|` frames. Charizard's first three notes sit at RMS 0.3125, 0.2849, 0.2708 — each slightly lower because of its own fade, with no collapse inside a note.
- **`sound_loop` IS applied**, and the reference's feature list marking it "unsupported" refers to its UI, not its data: cry0d's Ch5 arrives there with the block already duplicated, 14 entries where the raw table holds 7. `count` is the number of TIMES the block plays. Dropping it left the nine species on base cry0d short by exactly one block.
- **The one sound_loop's `target` and `count` are the only fields used**, so loop targets are stored as `"Ch5"` and not as literal labels.
- **Note positions are accumulated in clock units and rounded once**, not per note: the reference's `17,556 × frames` is an integer at its own rate, and rounding each note's delta instead of the cumulative position lost 4 samples across Charizard.
- **The pitch-shift cancellation is per note, not per sample**, and the offset is decided at the note's start against a cutoff one frame before the pulses are *scheduled* to end — the sum of the notes, not the length they render to, since the ring-out runs on past it. Measured over the corpus: of 689 noise notes, 620 keep the offset, 69 begin after the cutoff and never get one, and **63 span it**, so for those the pitch changes partway through. `noiseOffset()` is the single definition both the renderer and the timeline call, after they each carried their own copy and disagreed on every note (one in samples, one in seconds).
- **The ring-out is bounded only where the envelope can never empty.** Upstream does not implement `sound_ret`, so its last note rings until the volume reaches zero; a sweep of `0` means it never does, and an unbounded version rang one synthetic note for four million samples. Sixteen frames is the bound there. Bounding *every* note is wrong and was: a legitimate tail is up to fifteen envelope steps each a whole `|sweep|` frames apart, so 240 frames at the largest sweep, and a flat 16-frame cap silently truncated seven species by one frame each. **Those seven were then recorded in the checker as a "known set" on the reasoning that a tolerance beat a red test** — which was covering up a bound that would equally have hidden a truncation twice as large. Do not do that: a named exception list is for upstream quirks you cannot fix, never for your own truncation.
- **The data is diffed against the reference's own command tables**, and it is byte-identical across all 38 bases — every `frames`, `volume`, `sweep`, `freq` and `duty` byte in all 114 channels. That diff found the one remaining data bug: `fetch_gen1_cries.py` read the fade as an unsigned literal, while the tables use a **4-bit signed magnitude** (`pokered`'s macro packs the direction into bit 7 and notes that "a value of 8 is the same as a negative one"), so `square_note 12, 0, 8, 0` means *increase*. Stored as `+8` it is a fade out of a note whose volume is 0, which clamps at 0 and makes the note **silent** — nine notes across six bases. pokered's own engine agrees, writing `$8` to NR12 with the comment "fade in sound". The checker asserts the **range** `[-8, +7]`, not the nine values, so the next one is caught whatever it is.
- **The synthesis rate is 65,536 Hz, not the real 1,048,576 Hz**, because Web Audio caps a buffer at 96,000. The ratio is exactly 1/16, so nothing drifts.

`node scripts/check_gen1_apu.mjs` (92 checks) and `node scripts/test_check_gen1_apu.mjs` (39 mutation cases) guard it. Sixteen of those cases failed when first written and **every one was a real gap rather than a bad expectation** — the mutation test is the reason this section exists, so read it before trusting any assertion here that "looks obviously true". **The harness is not in `check_all.mjs`'s manifest any more**, so a green default run is not evidence that it would still catch anything; §3.G5 has the reasoning and the guard that stands in for it, weakly.

**The mutation harness had the disease this section warns about, and the rule now lives in §4.** A case's `expect` must name the assertion that actually detects its mutation; four of the 34 did not, and every one of them passed for an accidental reason because the matcher asked only whether the text appeared *anywhere* in the checker's output — and a checker prints an assertion's description whether it passes or fails. The worst of them had been calling itself a timeline test for its whole life while being a waveform test. `scripts/lib/negative.mjs` now decides this for all ten negative suites, and §4 has the full table of what each case was actually detected by.


**Where the 39 cases' time goes, and the two structural fixes.** 17 of them need the conformance loop and 22 do not — the split is decided by `CONFORMANCE_EXPECTS`, and getting that polarity backwards is what this paragraph used to do. The checker's native-rate conformance loop is **4.8 s of its 6.5 s**, so:

- The corpus is walked **once**, not four times. Four separate loops each rendered all 151 species and two measured the same thing; `renderSpeciesCry` is pure in `(cries, sfx, id)` with no options, so one pass answers all four questions. The per-species result is reduced to scalars and **dropped** — retaining 151 renders would hold ~78 MB of Float32Array alive, which is the one way this edit could cost more than it saves. Checker: 6.5 s → 5.5 s, and its output is unchanged line for line.
- The 22 cases whose detector is *not* the conformance comparison run against a fixture whose **copy** of the checker has that section removed: 5.5 s → 0.63 s each. `scripts/check_gen1_apu.mjs` gains no switch and no environment variable, because a supported way to skip the conformance comparison is how it would stop happening; the baseline always runs the whole checker. Eligibility is decided by `expect` alone, so there is no per-case flag to forget and an unflagged case runs everything.
- The one guard that makes the strip safe: the baseline runs a **second** time with the section removed and requires it to pass having dropped **exactly 4** of the 92 checks. A strip that took one check too many would leave the 22 cheap cases asserting against a silently narrower checker, and every one of them would still pass — they only require their own detector, which a narrower checker satisfies more easily, not less. **Nothing may live inside the stripped region that reads the repository**, because a fixture is not the file: an audit first written here compared the harness's 39 `expect` strings against the *stripped* copy, could not find the assertions 17 of them name, emitted 17 failures, and broke this very assertion. It now lives in `check_all.mjs`, which is not a fixture.
- Measured on this machine at `POOL = 4`: **~62 s → ~34 s**, with all 39 cases and all 92 checks intact. Cheapest first is wrong — the heavy cases are issued up front, so every trailing wave is short.

**Generating the conformance vectors has one trap worth writing down.** The reference's roster is a **0-indexed array**, so a dex id is `index + 1`. Reading it as `pokemon[id]` shifts every vector by one species and produces a plausible-looking file that matches nothing — including one species whose vector is not a species at all. The checker therefore asserts the two rosters agree on cry, pitch and length for all 150 before it trusts any of the audio, and the vectors carry those three fields for exactly that reason.

## G. The Two Cry Pages

`cries-gen1.html` and `cries.html` are driven over the Chrome DevTools Protocol by `scripts/check_gen1_page.mjs` (74 checks) and `scripts/check_cries_browser.mjs` (25 checks). Those exist because they are the claims no static checker can make — `check_gen1_apu.mjs` can prove the synthesis is right, but not that the page says true things about it or that pressing play does anything.

- **A playback cursor's guard must be `!== null`, never `> 0`.** `AudioContext.currentTime` reads exactly `0` on the first play, because the context has only just resumed, so `startedAt > 0` reported "not started" for the entire first playback and the cursor simply never appeared. Both pages draw one, from one clock, so the waveform's played region and the timeline's playhead cannot drift.
- **The waveform is cached in an offscreen canvas** and playing costs one `drawImage`. It is a thousand-odd line segments plus labels, none of which change while audio plays. The cache is bound with `const` from the first line — there is no "get the visible context, then reassign it to the cache" step, which is how `cries.html` ended up throwing a TypeError instead of drawing anything (below).
- **`cryPlayer.play()` resolves when a cry ENDS**, so a caller had no way to know when playback began or how long it would run. It takes an additive `onStart` hook carrying the duration and the clock reading; the player owns the AudioContext and is the only thing that can read that clock.
- **Both cry pages share ONE autoplay switch, and it must never fire on load.** `assets/js/cry-autoplay.js` mounts a `role="switch"` control with `aria-checked`, ON by default and persisted under its own localStorage key — one module rather than two copies that would drift apart invisibly. It is ON by default because both pages exist to be skimmed: comparing two species means clicking a chip and listening. **The rule that matters is the load case, and it takes a different shape on each page.** `cries-gen1.html`'s `select()` runs at boot, on every hashchange and from the reset button as well as from a chip, so there the switch is a *parameter* (`autoplay: autoplay.on`) and only the click handler passes it. `cries.html` reads the switch inside `probe()`, which is only ever reached from two click handlers — so the check there is on the call sites, and `check_cries_page.mjs` counts them on comment-stripped source: a fourth mention lives in a comment, and matching prose would make the count change when the code is explained. Expect this shape: on a page where one function serves boot and clicks alike, the feature flag has to be an argument rather than a read.
- **A mute nothing verifies is not a mute, so the second line is installed in the page.** Both CDP checkers keep `--mute-audio`, and that flag is the right *first* line — it mutes at the browser, so the AudioContext still runs and `currentTime` still advances, which is what keeps the playback assertions meaningful. It is not the whole guarantee, because it is a request: a mute that quietly stops working produces no red output, only a cry at a fifth of full scale, which is the worst pair of failure modes available. So `scripts/lib/mute-tap.mjs` is injected with `Page.addScriptToEvaluateOnNewDocument` — before any page script, so the module scope cannot race it — and replaces `AudioContext.destination` with a gain node at zero. Both pages wire their output through exactly that one call (`cry-player.js:196`, `cries-gen1.html:279`), so nothing reaches the speakers.
  - **Nothing either checker reads is downstream of that gain.** `currentTime`, `startedAt`, `duration`, `aria-pressed` and canvas pixels are all clock or DOM. The APU still renders every sample and `resume()` is still what unblocks the clock, so "pressing play reaches the synthesiser and moves a cursor" is still precisely what is measured. Only the last centimetre is discarded.
  - **And it is asserted, by reading the live `AudioParam` rather than a value recorded at install time** — so the question answered is "is the output muted *now*", and a page that opened the tap back up is caught. The probe sits **after the first play**, because the AudioContext is built lazily and a probe before that reads a tap that has not been asked to do anything. Verified by mutating the module in a scratch copy: `FAIL ... (0 AudioContext(s), gain null, the tap script never ran)` and `FAIL ... (1 AudioContext(s), gain 1)`. A mute that fails loudly is a mute; this one used to fail silently.
  - **One module, not two copies** — for the reason `cry-autoplay.js` is one module. Two copies of a mute drift invisibly, and the drift is noise.
  - **The limit, named:** it wraps `window.AudioContext`, so it does not cover `OfflineAudioContext` (which has no output device to mute anyway) or a page that reached the audio hardware another way. Neither page does.
- Both also take `CRY_PORT` (default 5500) so they can run against whichever Live Server port is actually up.
- **Never assert that an idle control is showing live state.** The timeline lane label read 播放中 for every unmuted channel, which was never true of anything.
- **A `details` group must stay open when it holds the current species.** Selecting a Pokémon used to collapse the list it had just been picked from, so comparing two relatives meant reopening the same group for every click.
- **The stored length byte is the frame count minus one.** Printing it as a frame count made every note in the command list read one frame short. The list shows the real count with the raw byte beside it, since the byte is what the ROM stores.
- **Count drawn pixels by ALPHA, and the assertion must be able to return false.** `cries.html`'s `drawWave()` bound its context with `const` and then reassigned it to the offscreen cache two lines later, which is a TypeError in module scope — the probe waveform never drew at all. `check_cries_browser.mjs` reported `ok` for the entire time, because it counted "dark" pixels in the top four rows while ignoring alpha, so every untouched pixel `(0,0,0,0)` scored as dark (2,400 of them, a perfect score), and because it asserted `typeof drew === 'number'`, which is true of `undefined` and therefore of no result whatsoever. It now measures ink across the whole canvas and requires more than 500 of it. Expect this shape on any canvas check: **a blank canvas is transparent, so alpha is the only thing that distinguishes "drew nothing" from "drew black".**
- **A slider's id is not the state field's name.** The three sliders were wired `for (const id of ['pitch','length','volume']) state[id] = value`, which worked for two of them and silently created a fourth property for the third: the Length slider's key is `lengthSigned`. So `state.length = 40` was written and `state.lengthSigned` never moved — the Length slider did **nothing at all**, same bytes rendered, same duration, bit-identical audio, while looking exactly like a working control. It is now an explicit `SLIDERS = { pitch, length, volume }` mapping, and `check_gen1_page.mjs` moves each slider and reads back the field it names — for Length the observable is the **sample count**, because a label can follow a readout that is wired to nothing while the sample count is the audio's own length. Expect this shape: a control can be inert and there is nothing in a screenshot to notice.
- **`overlap: true` is guarded in bare Node with a stub AudioContext, not in a browser, and its assertion is on the promise's SETTLEMENT.** `test_cry_overlap.mjs` (6 checks, 0.4 s, group `cry-page`) exists because the bug was `this.#overlapping.add(cur)` in `play()`, where `cur` is a name that exists only in `stop()`: every `overlap: true` call threw a ReferenceError, and `sorting.html` ends that call in `.catch(() => {})`, so nothing was logged, the cry still played, and the page looked fine. The consequences were silent — the promise REJECTED instead of resolving on `ended`, `onStart` never ran, and `#overlapping` stayed empty so `stop()` could not silence the voices it had layered. Asserting on settlement is the one thing the swallowed rejection could not hide. **A stub rather than a page is the determinism**, because Live Server reloads whenever a concurrent session writes a file, and a test whose subject is "does this promise resolve" must not depend on whether anybody is editing; `fetch()` is stubbed by path because the player asks for a relative url only a page can resolve.
- **Its mutant must be written OUTSIDE the repo, or `--prove-inputs` fails both ways.** The mutation case copies `cry-player.js` next to `cry-index.js` so the mutant's own `import './cry-index.js'` resolves, and it used to do that in `.cache/cry-overlap-neg/`, on the reasoning that "a temp directory outside the repo cannot resolve a relative import" — true of the mutant alone, false of the mutant plus its one import (`cry-index.js` imports nothing itself). Inside the repo those scratch reads are real reads of real paths, so `--prove-inputs` reported them **read but not declared**; and declaring them is not the fix either, because the same proof then fails the other way on **a glob that matches nothing** once the directory is deleted. The recorder ignores anything outside ROOT (`scripts/lib/record-inputs.cjs:106`), so a `mkdtempSync` makes this entry's input list **exact** rather than hand-maintained. It is the one entry in `cry-page` that is neither a page check nor a mutation harness.
- **The recorded cries play at the SAME loudness as the synthesised ones.** `cry-player.js` exports `DEFAULT_VOLUME = 3 / 15` and it is the default in *both* localStorage branches and the field initialiser. It was unity, and pressing play on `cries.html` or `detail.html` was genuinely startling — a recorded cry is a plucked square-ish tone with a wide dynamic range, and comparing twenty of them at full scale is not something to ask of anyone. It is 3/15 specifically because that is the master volume the Generation I lab presents as its default, so the two pages can be compared without one being louder for reasons that have nothing to do with the Pokémon. It lives in the **player** because the player owns the output gain; a page-level trim would have to be written twice and one page would eventually be missed. The per-call `volume` argument in `play()` is a separate per-play trim and still defaults to **1** — it multiplies into the shared gain, so defaulting it to the same number would square the level to 0.04.
- **The three sliders' rows must be pinned, not bottom-aligned.** `align-items: flex-end` aligns the one edge that differs: the hint under each slider is one or two lines of 10px text and they do not come out even, so 長度 was pushed up while 音高 and 音量 were pushed down — three labels at three heights. Each `.cg-slider` is therefore its own grid with `grid-template-rows: 20px auto 1fr`: the label always gets the same height, so the labels share a baseline and the tracks share a line, and the hint — the only part that varies — hangs below freely. The range also gets an explicit `height: 22px`, because an unstyled range's default height differs per engine and 2px there moves the whole track.
- **The intro's 6:4 split must leave the prose column AT LEAST its own measure.** The paragraph is set to 68ch, so a split that narrows the column below that does not change the line breaks — it just makes the grid the binding constraint and leaves the measure a lie written in the stylesheet. 7:3 gives ~700px at this page's width, well past 571px of measure, so the extra room buys nothing and costs the sprite its share; 6:4 lands at 590px. `check_gen1_page.mjs` asserts the column is not narrower than the measure, and reads the **grid tracks** rather than the sprite figure's box — `justify-self: center` shrinks that box to its 112px of content, so measuring it reports a 9:1 split for a grid set to 6:4.
- **The waveform ink is not the accent.** `--accent-gold` is gold in dark and **Poké Ball red** in light — by design, per shared.css's own comment on the light palette. Right for a link or a 3px outline, wrong for a 120px trace, where at ~4,000 points a red trace stops being a waveform and reads as one solid block. The traces and the playhead therefore use `--cy-wave-ink` (the gold in dark, a slate mixed from `--text-primary` and `--bg-card` in light); the **note bars keep the accent**, because the unshifted-tail marker has to stay a different colour from its parent bar and that difference is the load-bearing part of the crash explanation. Both values are theme tokens, so the no-raw-hex rule still holds.
- **The mix's sample count was printing seconds.** `${samples.length / SYNTH_RATE | 0} 個樣本` floors a sub-second cry to zero, so that line read **"0 個樣本" for all 151 species**. And it is now printed with a thousands separator, which broke the check that reads it — matching `\d+` against "62,541 個樣本" captures **"541"**, a different number that still scaled correctly with the slider, so nothing downstream could tell.
- **The four waveforms are four ROWS OF ONE STAFF, not a waveform above a timeline.** `cries-gen1.html` draws `mix / pulse1 / pulse2 / noise` the way the reference does — one band each, sharing a time axis — and each band carries its own note bars underneath its trace. Two reasons, and the second is the load-bearing one: **a waveform's horizontal extent *is* a timeline's extent** (same `total`, same interval), so drawing it twice as two stacked blocks asked the reader to hold an alignment in their head that the page could guarantee for them. One row per channel cannot disagree with itself. The mix is row 0 of the **same grid**, not a separate canvas above it — that is what makes all four share a left edge and a width, and a checker asserts the mix is `.cg-lane-mix`'s plot rather than a sibling of the staff.
- **Draw a trace, not a min/max envelope.** The reference draws a polyline through the samples, one point every four, and that is the only reason its lanes read as waveforms. A per-column min/max cannot show a Game Boy square wave at all: at 65,536 samples over ~700 columns a column holds ~87 samples and contains **both** extremes, so every column spans the full height and the lane comes out as a solid bar. Following the samples has a second benefit — a flat run needs no special case, because the noise LFSR shifts only every 128 samples, so most of that lane is a plateau and a plateau drawn as a line is a visible horizontal line. The envelope version needed a one-pixel branch for exactly that and still came out 96% blank (173 inked pixels of 34,656).
- **The lane traces hang from the bottom of their band, not centred in it.** The negative excursion is given up on purpose: a symmetric trace uses the band twice over and reads as a filled block, whereas hanging it frees the lower half for the note bars, so a lane reads as *sound above, notes below*. The low level is not discarded — it is the line on the zero line, so a square wave shows its two levels, which is the duty cycle the command list prints as a percentage.
- **Every one of the six synthesis bugs above was found by comparing against rgmechex's OWN OUTPUT, and that is the page to thank.** [rgmechex.com/tech/gen1cries.html](https://rgmechex.com/tech/gen1cries.html) is the reference synthesiser; `gb-apu.js` is transcribed from its source rather than reasoned about, and the six documented failures (per-quarter-period duty rotation, continuously-decaying envelope, time-stretched noise, single-field noise rate, no ring-out, byte-minus-0x80 length parameter) were each written wrong first and each only surfaced against that page's output. **This is recorded here rather than on `cries-gen1.html` on purpose:** the page's 出處 section names the reference and the behaviours taken from it, which is what a reader needs, and the story of our own debugging is not theirs to read.
- **A waveform must be drawn at full scale even when the audio is quiet.** The APU multiplies the mix by `clampVolume(volume)/15`, so at the default of 3 the array the page holds is a fifth of full scale — and the mix was drawn from it directly, so the whole thing looked like a whisper *and changed shape as the reader dragged the volume slider*. `unmasterGain()` inverts the APU's own factor; loudness belongs in the ears, a waveform is a picture of the sound's shape. A master volume of 0 renders all zeros, and that lane says 音量 0 rather than drawing a flat line, which would be a different and wrong claim (「this Pokémon is silent」).
- **Two axes in one row: bars are positioned in SECONDS, the waveform is indexed by SAMPLES.** Dividing a note's start by the sample count puts every bar under 0.02% of a 62,541-sample lane — seven bars stacked on the left edge, and a check that only counted them saw nothing wrong. `check_gen1_page.mjs` reads the last bar's right edge, the one number that moves when the two are conflated.
- **A muted lane changes colour rather than only opacity**, because gold at 0.28 alpha over a dark panel is still gold, so the dimming communicated nothing. Measured as a colour distance between two lanes, since "it looks dimmer" is not something a checker can be asked about.
- **The picker's 151 sprites are asserted as a BINDING, not as a download count.** All 151 chips are `loading="lazy"` and the panel is long, so a few seconds in only some 50 have decoded. An earlier version of the check asserted "every sprite in the viewport has decoded" and failed — that measures Live Server's throughput, not the page, and the only way to satisfy it would be to delete the lazy loading that is correct. What is checked instead: every chip has a sprite, each one's `src` is **its own species'** file rather than a shared placeholder, all are lazy, and the one image the reader is looking at — the selected species' — decodes at 96px, which is the only failure mode the binding can have.
- **A clock read every frame and written nowhere is the same bug as a dead slider.** `cries.html`'s probe cursor computed `(progress.now - progress.startedAt) / progress.duration`, and `progress.now` was initialised to 0 and never assigned again — so the ratio was negative, clamped to 0, and the cursor sat at the origin for the life of the page. `cry-player.js` now exports `now()`, because the AudioContext is private to the player and a page cannot fake that clock on a different timebase without drifting against the `startedAt` it was handed. Two instances of this shape on one page, which is the tell: **a field that is read but never written is a feature that was never built.**
- **The probe waveform's played region is painted in the Pokémon's own colour**, not with a dark wash. The wash is the Generation I lab's device and it reads as "already played" only because that trace is gold on a dark panel; on a neutral slate it is a dirty smear that says nothing about *which* Pokémon is sounding. So `drawWave()` keeps the trace as **geometry** as well as pixels — a 220-segment `Float32Array` — and `blitProbe()` re-strokes the played part over the neutral one, in the sprite's average `rgb` (the same value detail.html puts on its hero card). **The accent keeps BOTH endpoints of every envelope segment** — `probeTrace` is four numbers per sample (x, top, bottom), not two. It was two, holding only the top, and the played region drew as a single line along the upper envelope: playback showed the top half of every bar and nothing below it, which is not the same waveform in another colour but half a waveform. The accent also strokes at the **same weight** as the neutral trace, because a heavier accent made the played half a different-looking shape rather than the same shape recoloured. `check_cries_browser.mjs` counts the accent's ink either side of the zero line for exactly this reason.
- **A checker that presses play must CONFIRM the press landed, because a detached node makes a click a silent no-op.** `check_cries_browser.mjs` captured the probe's play button once and clicked it 140 ms later — and autoplay is ON by default (§3.G), so the cry already sounding ended in between, and `renderProbe()` writes `#probe-play`'s `innerHTML` on every play and every stop (`cries.html:496`). The captured node was **detached**, a detached node does not bubble to the delegated listener on `#probe-play` (`cries.html:812`), and the click did nothing: 60 samples over 1.28 s read `aria-pressed=false` and zero accent pixels, every time. Nothing noticed, because **the measurement did not require playback** — the scan loop's first sample landed inside the *autoplay's* final frames, so the reported `maxX` was wherever that unrelated playback happened to be. It surfaced as a flake (`x=669` idle, `x=696` under load, one green and one red across a 5%-wide band straddling the 95% threshold) and would have been "fixed" by widening the tolerance, which is the trap: **a control bug wearing a tolerance's clothes.** The button is re-queried at every use, the press is retried until `aria-pressed` flips, and `pressing play starts playback` is now its own assertion — the one whose absence let 19 green checks measure a click that never fired. Expect this shape wherever a page re-renders a control's markup: the same failure is documented in §3.B1 for `colors-generator.html`'s preset grid.
- **Which frame an assertion reads decides whether it is a measurement or a coin flip.** The played-region checks now take two frames: the **fullest** (most accent ink — the last frame painted before the cursor clears) carries presence, left-anchoring and above/below-the-zero-line, where more ink is strictly better evidence; the **earliest** (first frame carrying any accent) carries "the far end is still unplayed". On the fullest frame the playhead is at the end of the cry, so its rightmost accent pixel lands at 92-97% of the width and whether that clears a 95% bar is a matter of where the final `requestAnimationFrame` fell — measured at `maxX` 685/704/716/719/722 across five runs. On the earliest frame ~96% of the canvas is unplayed, and the value is now **4-23 against a limit of 686**: identical on an idle machine and under eight `yes` processes, which is what "load-independent" has to mean. The early `n > 400` break the loop used to end on had to go — it stopped sampling a few columns in, which would leave both frames the same and make the far-end claim vacuous.
**The two regions are drawn as two DISJOINT regions, not one over the other** — the cache is blitted only into the unplayed span and the accent stroked only into the played one. Stroking the accent on top does not work on this waveform specifically: it is a peak envelope, 220 vertical segments from each sample's top to its bottom, so at this width consecutive segments merge into solid bars and a 2px accent on the same path as the 1px neutral line puts the neutral line **down the middle** of the accent. All that shows is a tan fringe either side of a white core, which is exactly what "it looks like it is behind the grey" was. Because nothing overlaps, the accent can be as heavy as it needs to be to read at all. `check_cries_browser.mjs` locates the accent by colour **derived from that species' rgb**, not by comparing two thirds of the canvas: at the frame the loop stops on, the played region is a sliver, so a thirds-based mean compares two neutral bands and finds nothing. Its first version also wrote the predicate as channel tests tuned for a reddish accent, which excluded Charizard's tan exactly — so build the predicate from the colour you are looking for.
- **A filter and a scroll position are different quantities and must not share a field.** `cries.html` had one `state.gen` serving as both the generation filter and the page counter, so `render()` sliced `state.gen * PAGE_SIZE`: 第 1 世代 asked for 60 cards out of all 1,025 and showed exactly what the unfiltered page showed, with `aria-pressed` claiming the chip was on, and the sentinel's `state.gen++` re-picked a generation on every scroll. It is now `state.gen` (filter, narrowed by the pokemon record's own `generation`) plus `state.pages` (batches on screen), and `computeAxisRange()` reads the filtered set too — otherwise the meters stayed scaled against all 1,025 while the cards showed one generation.
- **The master volume is on the channel scale's own 0..15, and the page presents that same 0..15 slider, defaulting to 3** — about a fifth of full scale, which is comfortable where 15 is not. `sliderToMaster()` is gone, per the rate-independence note above. `check_gen1_apu.mjs` renders species 6 at volume 3 and at volume 15 and requires the peaks to stand in a ratio of one fifth: the mix divides by three and never normalises, so a ratio of peaks **is** a ratio of volumes. Note which mutation that actually catches — squaring the curve, which stays in range and leaves every waveform byte identical. The obvious one, `/ 15` to `/ 10`, is caught by the clipping check instead, because a full-scale render then exceeds 1.0; a case must name the assertion that detects it.

**`assets/data/cry_features.json` (generated by `scripts/analyze_cries.py`)** is one 34-number row per roster file — `dur` `peak` `rms` `zcr` `centroid` `rolloff85` `flatness` `flux`, then 13 MFCC means and 13 MFCC standard deviations — for 1,025 latest and 649 legacy cries. 499 KB, and no similarity matrix: 1,025² floats is 4 MB, and the browser multiplies the rows it already has.

- **Every file is resampled to 16 kHz first, and that is not cosmetic.** The corpus spans **fifteen sample rates**, 8,000–48,000 Hz, with 784 files at 32,728 Hz against 120 at 44,100 Hz. A mel filterbank built over each file's own Nyquist gives those two groups different meanings for the same coefficient, so a search would partly rank which encoder produced the file. 16 kHz is justified by measurement: 90.6% of energy is below 4 kHz and 98.2% below 8 kHz.
- **`peak` and `rms` are measured on the decoded signal, not after resampling**, because both are independent of sample rate and FFT resampling smooths `25.ogg`'s peak down from 1.0391 to under 0.94 — which would hide the fact that the corpus is not clipped. The measured maximum is 1.2111. Consumers drawing an envelope clamp at draw time.
- **legacy and latest are NOT comparable.** Centroid medians are 1,327 Hz against 2,992 Hz, flatness differs by two orders of magnitude, every legacy file is at 10,512 Hz. That is a difference in how the two sets were recorded, not between the Pokémon. They are stored under separate keys, range-checked separately, and the checker asserts the offset is *still present* so a change that quietly merged them is noticed.
- **`node scripts/check_cry_features.mjs` (24 checks)** and `node scripts/test_check_cry_features.mjs` (19 mutation cases) guard it. The assertion that earns its keep is **every dimension must vary across the corpus**: a constant column means a filterbank that collapsed or a DCT that never ran, which passes every shape and NaN check while the search degrades to chance.
- **"Most similar cry" cannot be a similarity ranking here.** Measured within one corpus: same-family pairs average 0.2076 against 0.0075 for unrelated pairs — a real separation — but top-1 same-family accuracy is **2.1%** against a ~0.1% random baseline. Log-mel mean+std (26/40 bands), MFCC 13, MFCC 20 and a 40 ms window all land between 1.5% and 2.1%; nothing is meaningfully better, because each modern cry was composed independently and evolutionary relation does not predict how a Pokémon sounds. These features are honest timbre descriptors. Present them as axes, not as a semantic ranking.
- `cries.html` therefore ships the search as a **音色** ranking with the measured figures on screen — top-1 2.1%, top-20 12.6% against a 3.2% baseline — and says 音色而非血緣 in the DOM. Two consequences worth knowing before editing it, both found by measurement rather than by reading:
  - **Scores must be standardised per dimension before they are compared.** Raw, `centroid` runs to 3,167 while `flatness` runs to 0.7, so an unstandardised cosine returns **1.000 for every pair** and the list looks perfectly plausible while being decided by two dimensions. `indexSet()` computes means and deviations **per set**, not once, because the two recordings differ enough that a legacy vector standardised with latest's statistics is not the same measurement.
  - **No weight preset may activate a single dimension.** Cosine over a 1-D vector is always ±1, so a preset called 「只看明亮度」 returns 1.000 for every neighbour and orders them by distance *descending* — the exact opposite of its label, silently. Ordering by one axis is what the sort dropdown is for. `similarTo()` still falls back to absolute distance if only one dimension is ever active, because that failure is silent rather than loud. `check_cries_page.mjs` asserts both.
- `node scripts/check_cries_page.mjs` (64 checks) and `node scripts/test_check_cries_page.mjs` (35 mutation cases) guard the page's claims. Five of those cases failed when first written and each was a weak assertion rather than a bad expectation: a `key:` regex that matched the weight presets as well as the axes, a `cp-` scan that found the comment explaining why `cries.css` must not claim one, a roster-gate check that tested for the identifiers instead of the import, a hardcoded-row detector whose threshold also flagged the probe's legitimate `[0, 1, 2, 3]` MFCC readout, and a `state.gen` write-count that balanced because the `IntersectionObserver` it was supposed to exclude is defined *after* the handler — so a mutation moving the sentinel onto the filter passed. The last two are the §4 rule in its purest form: the count has to be a count of something that cannot be on both sides, and the forbidden region has to be bounded at the thing that actually commits the sin.

## G1. The Spectrum Page — a Port That Is Checked Against Its Own Extractor

`spectrum.html` draws a mel spectrogram of any cry in the corpus, in all three sources at once: the 1,025 latest recordings, the 649 legacy ones, and the 151 Generation I syntheses re-rendered through `gb-apu.js`. It is a separate page because it answers a different question from `cries.html` — that one is a browsable index, this one is an instrument — for the same reason §3.B1 splits `colors-generator.html` from `color.html`, and `cries.css` is already shared by two pages, so the new rules live in `spectrum.css` and every one is `sp-`.

**NO SPECTROGRAM IS STORED.** The band is already inside the repo: `analyze_cries.py` computes 26 mel bands per cry to get its MFCC, so the spectrum it describes is one function away. A stored bank would be 1,025 × 64 × 26 bytes, ~2.3 MB once base64'd, and would go stale the moment a cry was re-encoded. Recomputing one cry on demand is ~80 frames of 512-point FFT. The second reason is that a port can be **checked against the thing it ports**; a stored image is a claim, this is a measurement that carries its own error bar onto the page.

**`assets/js/cry-spectrogram.js` IS A PORT OF `analyze_cries.py`, and `check_spectrogram_port.mjs` (55 checks) differences the two on a synthetic signal both can synthesise from arithmetic alone.** "I read the Python and wrote the JavaScript carefully" is not evidence. The checker runs the extractor's *own imported functions* against this module's, and the tolerances are grounded in measurements rather than in the observed number.

**`analyze_cries.py`'s `resample()` has TWO BUGS, and they are recorded here rather than fixed, because fixing them moves the stored table.** Both are load-bearing for what the page may claim:

  - **Amplitude.** It multiplies the kept bins by `n_out / n_fft` before the inverse transform. Zero-padding a signal to `n_fft` does not change `X` — the transform is just sampled on a finer grid — so `irfft(X, n_fft)` returns `x` exactly and the amplitude-preserving scale is **1.0**. The proof needs no argument about spectral content: **a 100 Hz tone resampled from 32,728 Hz to 16 kHz comes back at 0.1465 of its amplitude**, and no Nyquist cut can be responsible for a 100 Hz tone. Measured over fifteen source rates and durations, `scale = 1.0` holds a tone to within 0.4% while `n_out / n_fft` loses between 15% and 95%.
  - **Cutoff.** It keeps `n_out / 2` bins of an `n_fft`-point transform, and those bins are spaced `sr_in / n_fft` apart, so its top kept bin sits at `(n_out/2) · sr_in / n_fft` Hz — 4,102 Hz for a 0.7 s signal, against the 8,000 Hz a resample to 16 kHz must keep. **`n_fft` follows the file's DURATION, so the cutoff does too**: measured across the 1,025 latest cries it lands between about 4.4 kHz and 8 kHz. Every stored row therefore describes a signal band-limited at a frequency that depends on how long the file is.

What that costs was measured, over 23 species spanning every source rate and both ends of the duration range: **31 of the 34 features have a median relative difference of `0.00e+00`**, with a worst of 1.5e-1 on `m2` and `m12` and only on the cries carrying real energy near 8 kHz. The wrong cutoff turns out to be cheap because the cries barely use the top of the band — the same fact `analyze_cries.py` cites when it picks 16 kHz. **`m0` alone moves systematically**, by exactly `log(n_out / n_fft) · √26`, because DCT row 0 is `√(1/26)` in all 26 entries while every row above zero sums its basis to nothing and cannot see a constant at all. Across the corpus that factor spans 1.741 in natural log, which is **8.88 in `m0` units against a stored spread of 37.58** — so roughly a quarter of `m0`'s variance is a function of how long the file is, and `cries.html` standardises `m0` before its similarity search.

**The module does NOT copy either bug.** It uses scale 1.0 and the correct Nyquist, because a spectrogram whose dB axis is 15–95% low and whose top octave is rolled off at a duration-dependent frequency is not a picture of the file. It exports `UNCOMPARABLE = [peak, rms, m0]` and `M0_SCALE_OFFSET = √26`, and the checker asserts the m0 relationship as an **IDENTITY rather than a tolerance** — satisfied by exactly one relationship between the two numbers, where a wrong filterbank, hop or window moves the observed value by whole units. A tolerance would have been satisfied by a mutation whose own difference is under 5%, and one of the negative cases is that mutation.

**`UNCOMPARABLE` HAS TWO CAUSES, and the page says so in two sentences.** `peak` and `rms` are a *limit of the browser*: they are measured on the signal at its true source rate, which is unrecoverable because `decodeAudioData` resamples to the AudioContext's rate first (§3.F, `cry-player.js` point 3). `m0` is a *defect upstream*. Conflating them tells a reader to distrust a tool when the tool is right, so the panel names all three and gives both reasons.

**THE PAGE REPORTS FIVE FEATURES AND NOT A RELATIVE DIFFERENCE FOR THE OTHER 29, and that was measured rather than chosen for taste.** Decoding `latest/1.ogg` at its own 32,728 Hz — so no resampling happens at all — the browser and `cry_features.json` differ by a **median 5.5%** across the 31 comparable features and by **1,181%** on the worst. That worst is an `ms` column: a standard deviation of MFCC values whose stored magnitude is about 0.002. Thirteen of the 34 are like that, and a relative difference on them reports a large disagreement about a number that is nearly zero. At the 48 kHz device rate the same file is **27%** off on the median and 27% off on the centroid, because that adds `decodeAudioData`'s own resample on top of the decoder difference. So the page prints absolute differences for the five that are both large in magnitude and well conditioned — `dur`, `zcr`, `centroid`, `rolloff85`, `flux`, whose relative differences are 0, 0.0005%, 3.6%, 2.7% and 0.22%. **`flatness` was in that set on the reasoning that it is a ratio bounded by 1 and therefore stable, and measured 31%.** It is scale-invariant and ill-conditioned — the geometric over the arithmetic mean, a ratio of two nearly equal numbers — and being inside `[0,1]` says nothing about how sensitive it is. That is the second time in this project a property which sounds like a guarantee turned out to be an unrelated one, and `check_spectrum_page.mjs` asserts its absence.

**A LIVE CURVE IS A SECOND MEASUREMENT, AND THE CAPTION SAYS SO.** The `AnalyserNode` tap hangs off the shared gain node (so a mute silences the measurement too, which is a true reading rather than a defect) and returns 1024 **linear** bins at the **device** rate over a 2,048-point window with smoothing 0.3 — about 42.7 ms against the offline 25 ms with none. Folding those into the same 26 mel bands approximates the offline path rather than reproducing it. It is on the page because it answers "where is the energy *right now*" at 60 frames a second, which an offline grid cannot do at all, and the caption names all three differences rather than letting one reading cover them.

**THE REVEAL IS NOT A STREAMING ANALYSIS, and the intro says so.** The whole spectrogram is computed before the reader presses play; playback uncovers it left to right at the AudioContext's own clock, so it is one set of pixels moving, not a second measurement. The axes are drawn *after* the veil rather than before, or the frequency labels would dim with the data and the reader would lose the one thing that does not change during playback. The unplayed region is veiled with the plot's own ground colour and not a neutral wash, because on a near-black ground a grey veil reads as a second data series. Under `prefers-reduced-motion` there is no veil and no playhead at all: the plot is the measurement and the wipe is only time passing.

**The plot is NEAREST-NEIGHBOUR on both axes, and the blockiness IS the resolution.** The horizontal axis is time on a fixed 10 ms hop, so a 0.18 s cry — the shortest in the corpus — really does put ~55 pixels between two measurements, and smoothing across them would draw a curve the analysis never made. The colour ramp is declared once in `spectrum.css` as `--sp-0`…`--sp-5` and read back with `getPropertyValue` into a 256-entry LUT, because the legend gradient is built from the same six custom properties and two copies of six hexes is two things to keep right. **The ramp is deliberately theme-INDEPENDENT** — dark means quiet in both themes — because re-mapping a colour scale per theme would mean the same number in the same cell reading as two different things, which is the one thing a scale must never do. What changes per theme is everything around it.

**`cry-player.js` gained three ADDITIVE methods and no behaviour changed.** `decoded()` shares the existing `#cache` so the page does not fetch and decode a second time; `playSamples()` exists so the Generation I synthesis plays through the *same* AudioContext, clock, gain and analyser as the recordings, which is what lets a reader put a synthesised cry and a recorded one in the same spectrogram; and `spectrum()` reads the live tap. The `decimate-by-two` fallback is load-bearing rather than defensive, because 65,536 Hz is the rate the synthesis arrives at and that allocation is what browsers refuse. `mountAutoplay()` gained a `className` option so a third page can share the one module instead of copying it — **one module, three prefixes, zero copied markup**, for the reason §3.G gives for the mute.

**`node scripts/check_spectrogram_port.mjs` (55 checks), `node scripts/test_check_spectrogram_port.mjs` (11 cases), `node scripts/check_spectrum_page.mjs` (196 checks), `node scripts/test_check_spectrum_page.mjs` (41 cases) and `node scripts/check_spectrum_browser.mjs` (72 checks) guard it.** The port's negative suite includes the two bugs above, deliberately copied in, and a periodic-Hamming-window case that **only the log-mel grid identity catches** — the 34 numbers are means and standard deviations over 68 frames, so a small per-frame error cancels out of them and is still visible in the cells. Three of its cases named the wrong detector when first written, which is §4 arriving from a new direction: a case that names an assertion which happens to be tripped for an unrelated reason is not a case. `check_spectrum_page.mjs` compares the module's constants to the extractor's **by value**, evaluating `SR = 16_000` and `int(round(0.025 · SR))` rather than pattern-matching them, because a regex that matched bare digits would have "compared" all nine constants while checking one. §3.G1a is the layout half.

**A LOADER ERROR IS NOT A TEST FAILURE, AND TWO PLACES HERE PROVED IT.** The port checker's subprocess resolves `../.venv/bin/python` relative to itself, so a `mkdtemp` in `/tmp` has no `../.venv`: the checker prints its SKIP line, exits 0, and every negative case would report FAIL having run zero assertions. The negative suite therefore places its trees beside a **symlinked venv**, and its baseline case is what proves the tree is sound. The other is `--prove-inputs` reporting `analyze_cries.py`, `shared.js`, `gb-apu.js` and `gen1_cries.json` as "declared but not read" — correct, since the page fetches those in the browser and the checker only saw its own imports. Rather than delete the entries, **each became a claim**: the extractor is read to assert the nine constants are declared at module level, `shared.js` to assert NAV carries the page, `gb-apu.js` to assert `SYNTH_RATE` is 65,536, `gen1_cries.json` to assert all 151 rows carry the two bytes `renderSpeciesCry` needs. A declared input nothing opens is an input whose edit will not invalidate the checker.

### G1a. A Section With Two Tracks And No Wrapper — 213 Checks On The Wrong Question

`.sp-about` shipped with a `</div>` whose **opening tag was missing**. It was not a styling mistake and not a copy problem: the closing marker was there, correct, for a `<div class="sp-about-body">` nobody had written. The stray marker closed `.sp-page` instead, and **two independent things broke at once**, both measured at a 1113px viewport where `.sp-page` is 787px wide and the two tracks are 435px and 290px:

- **The 6:4 grid auto-placed its SEVEN unwrapped children as four unrelated rows.** `h2` alone in the wide track with **130px of void beneath it**, while the paragraph that belongs directly under it rendered in the 290px narrow track at **24 CJK characters a line**. Only the row holding the two `<details>` paired up, and that was coincidence. A 2-track grid has no idea a reader expects two *columns*; it has seven children and two slots, and it fills them in document order.
- **`</section>` then matched nothing**, so `.sp-about-live` — 「即時頻譜圖的參數」 — fell out of `.sp-page` and became a direct child of `<main>`, at **y=2648 against `.sp-page`'s bottom edge at 2622**. The one block whose entire job is to be read BESIDE the offline spectrogram rendered as a stranded full-width card below the whole page, and lost the comparison that is its only reason to exist.

**170 static and 43 CDP checks stayed green, and that is the finding rather than an excuse.** Every one of them asked whether the prose and the CSS rules EXIST. The claim being protected is different in kind: *no closing marker in this document points at the wrong element*. Nothing about a page's behaviour depends on that being wrong, which is exactly why 213 assertions had nothing to say about it. The new **tag-balance check** is the assertion whose absence let it ship, and it is deliberately about the document rather than about one section — a section-specific check would have caught *this* stray marker and sat silent on the next one, which will not be in `.sp-about` and will not have a check waiting. Raw-text elements are skipped rather than tokenized (this file's own theme bootstrap is full of `&&` and `<`), and the base is the whole comment-stripped document rather than the module-`<script>`-truncated `markup` the other checks use, because a document sliced mid-`<body>` is imbalanced by construction and reports two phantom errors on a correct file. **Expect this shape wherever a region was edited by inserting one line at a time: a closing marker is evidence of an opening tag, and the two drift apart silently because nothing downstream consumes the difference.**

**The fix was INSERTING ONE LINE, not deleting one** — the `</div>` was already correct and waiting. `.sp-about-body` also needs `min-width: 0` for `.sp-intro-body`'s reason: a grid item's `min-width` defaults to `auto` and is floored by its own min-content, so the track's `minmax(0, 6fr)` is opt-out unless the item declines it.

**A COMMENT IN THIS REGION HAD ALREADY CLAIMED THE WRONG RELATIONSHIP, and fixing the layout did not fix it.** The note above the parameter column asserted it 「stays reachable as the canvas's `aria-describedby`」. Measured: `#sp-about-live-h` is referenced by exactly one attribute in the whole repository — `aria-labelledby` on its own container — and the canvas's `aria-describedby` is `#sp-live-alt`, the caption under the curve. That is the *correct* relationship (§3.G1's note on `#sp-live-alt` is right to insist the caption may not shrink to nothing), and it was the comment that was false. This is §4's shape exactly: a claim so precisely worded it reads as verified, verified by nothing.

**THE RHYTHM WAS FOUR NUMBERS WHERE THE CLAIM WAS ABOUT A RATIO.** Measured over the five top-level blocks of `.sp-page`: `.sp-intro` 20px, `.sp-hero` / `.sp-live` / `.sp-numbers` **22px each**, `.sp-about` 26px. 時頻圖, 即時頻譜圖 and 量測數值 are three views of ONE measurement, and 22px said nothing about that — the kind change carried the same interval as the kind continuity, which is the definition of no rhythm. Now two tokens: `--sp-band-gap: 14px` inside the band, `--sp-band-sep: 40px` at its two boundaries, **0.64× and 1.8× against the 22px they replaced**, because the claim is the ratio and anything inside 18–26 would have kept the page exactly as flat. Measured gaps between rendered boxes: **40 / 14 / 14 / 40**, at 1280px and at 429px alike, since these are margins. `.sp-about`'s is `0` and that is not a rounding — it is the last child of `.sp-page`, so its 26px had nothing under it and `.sp-main` owns the bottom whitespace at 64px like every other page here. Asserted as the **declared tokens plus the four rules that consume them**, because a test that reads four resolved margins can be satisfied by four identical literals, and the "all four back to 22px while the tokens stay declared" case is in the negative suite for that reason.

**對表's HEADER HAD FOUR LABELS OVER FIVE COLUMNS, and its labels were rendering at the DATA's emphasis.** Two separate defects in one block, and the second was only visible once the first was fixed:

- `.sp-x-head > dd` and `.sp-x-rows > dd` share one `grid-template-columns` of **five** fixed tracks (`60px 14px 58px 46px 92px`). The header carried four spans, so the 92px track — the one printing 「差 296」 on every row — had **no header cell at all**. 差 *X* is self-describing in its text, which is why nobody noticed, but three named columns and one anonymous one reads as an overflow past the table rather than as a fourth quantity. The fifth label is 「絕對差」, on **`class="sp-where"` and not a header-only class** — `check_spectrum_page.mjs`'s class audit caught that first attempt, correctly, and it is kept as a negative case: a fourth class for one label is a column identity that exists in the header and nowhere else, which is the exact drift the shared classes exist to prevent.
- The header's spans borrow the rows' classes **on purpose** (one set of tracks, one set of column identities), and `.sp-x-got` and `.sp-x-rel` also carry `color: var(--text-primary)` and `font-weight: 600`. At equal specificity the *later* declaration wins, so `.sp-x-head`'s own `color` did nothing for three of its four children. Measured in light theme: 這一頁算的 and 相對差 at `rgb(15, 23, 48)` / 600 against 離線表存的 at `rgb(56, 66, 95)` / 400 — a header where two of four labels are bold and one is dimmer, which reads as emphasis that is not there. The reset is `.sp-x-head > dd > span`, and **the descendant combinator is the point**: `.sp-x-head` alone is (0,1,0), ties with the row classes, and loses on order, so a fix that only worked by being written later would be undone by the next rule anybody adds to the file. Asserted on the selector shape for that reason, and the "moved onto `.sp-x-head`" case is in the negative suite — that mutation leaves a stylesheet that plainly contains a rule setting the header's colour while the page looks exactly as it did before the fix. `check_spectrum_browser.mjs` measures the rendered colours, and separately asserts the **rows** still carry 600, because a check satisfied by flattening the block is not a fix.

**THE SINGLE-CHILD WRAPPER IS GONE, NOT EMPTIED.** `.sp-hero-head` held exactly one element — this section's `<h2>` — inside `display: flex` with a `gap`, left over from when a 28px sprite chip lived beside the chart's title. It renders identically to no wrapper and cannot be told apart from one in review. Its absence is asserted in **both** files, because a rule with no element and an element with no rule are the two halves of the same drift, and the class audit already covers the second.

**THE CHECKER'S OWN HEADLESS VIEWPORT IS NARROWER THAN THE BREAKPOINT IT IS GUARDING, so the two-column claim had to be measured at a different width than everything else.** `check_spectrum_browser.mjs` runs at a default `innerWidth` of **756px**, and `.sp-about` stacks below 900px — so a "the section is two columns" assertion there is vacuously true of a collapsed layout, which is §3.G's shape again. It widens via `Emulation.setDeviceMetricsOverride`, **asserts the override took effect** (a Chrome that ignores it fails rather than silently reporting the narrow layout's answer), and then restores the width and **asserts the restore**, because every measurement after it is a canvas pixel count taken at a specific width. Note that the `--window-size` Chrome flag is **clamped to the host screen in this environment** — measured `innerWidth` 1113 for a requested 1440, and 573 for a requested 900 — while `Emulation` honoured 1280 and the `--screenshot` path honoured 1440 exactly. **A screenshot taken at a width the browser did not have is not evidence about that width**, and that is worth knowing before quoting a viewport measurement from this machine.

**`check_spectrum_page.mjs` is 196 checks, `test_check_spectrum_page.mjs` 41 cases, `check_spectrum_browser.mjs` 72.** The 11 new negative cases are the ones worth reading first, because the headline case reproduces the shipped defect exactly — delete the wrapper's opening tag, require the **balance** assertion to be the detector rather than one of the three section-specific ones that also go red. Of those three, the balance check is the only one about the document rather than about one section's intended layout, which is why it is the one that would have caught the next stray marker.

## G6. State Shared Through Storage Is Not State a Per-Page Test Can See

**A page's own default was silently muting three other pages, and NO test could see it, because the bug needed a VISIT ORDER.** `sorting.html` starts with its cry switch off, which is correct — it is the only page that can fire a sound every few milliseconds. It expressed that as `cryPlayer.muted = true`, and that setter **persists** (`#save()` writes the site-wide `pokemon-algorithm:cry-volume` key), so merely *loading* the page wrote `{muted: true}` and `cries.html`, `detail.html` and `spectrum.html` then read it back and went permanently silent — with no control of their own to undo it, because `rg -l "cryPlayer.muted" *.html` named **one file, and it was not one of them**. `cries-gen1.html` was unaffected throughout, because it builds its own `AudioContext` and keeps its mute in per-lane memory that is never written anywhere — which is exactly why the report read as two unrelated bugs ("cries and spectrum are silent, but the Gen I lab is fine").

**Why nothing in a 43-entry suite saw it: every checker runs on a fresh `--user-data-dir`, so `localStorage` starts EMPTY on every run.** The defect requires that a page which writes the key be *visited before* a page that reads it, and no per-page checker can express a sequence. This is a distinct entry in §4's list of ways a green run can be wrong, and it is not fixed by asserting anything louder about any one page — the assertion has to be **cross-page in one profile**, which is why `check_cries_browser.mjs` now navigates to `sorting.html` before it asks whether `cries.html` can make a sound at all.

**THE FIRST FIX CLOSED ONE GATE AND LEFT A WORSE ONE, and the shape is the point.** `muteForView()` — apply the mute, skip `#save()` — closes the load path. But `#save()` is also reached from the **volume setter**, and it serialised the *effective* mute, so the page's default rode out through a slider the reader was using for an unrelated reason. Measured, in order:

```
load sorting.html       → key null
drag the volume slider  → {"volume":0.55,"muted":true}
open cries.html         → silent, and no control on that page to undo it
```

A page default that reaches storage through an unrelated control is **worse** than one written on load, because it presents as the reader's own doing. So the mute is two fields: `#storedMuted` is the reader's choice and the only one written; `#viewMuted` is a page's default and lives in memory. **One field cannot carry both decisions because `#save()` cannot tell them apart** — that is the whole reason, and it is a data-model problem rather than a missing `if`.

**`#applyGain()` AND `get muted()` MUST BOTH READ THE OR, and each wrong answer fails silently in a direction the reader cannot undo.** `#storedMuted` alone makes `sorting.html` **loud by default**, contradicting the very intent its own comment records; `#viewMuted` alone ignores an explicit un-mute and leaves `cries.html` silent forever for someone who turned sound on. Neither throws. `sorting.html`'s single reader of the flag (`if (cryPlayer.muted) return`) needed no change, which is the only reason this stayed a two-line edit.

**A WAIT FOR NAVIGATION OVER CDP MUST BE GATED ON SOMETHING ONLY THE DESTINATION HAS.** The cross-page wait was gated on `nav[data-nav] a` — which **the page being navigated away from** also has, so `booted()` returned instantly against the old document and the next line threw `TypeError: Cannot set properties of null` on a page that was not the one being read. `Page.navigate` resolves when the navigation is committed *to the browser*, not when `Runtime.evaluate` reaches the new document, and the two documents share an origin — so **anything they have in common is evidence of nothing**. It waits on `#audioVolume`, which only `sorting.html` has.

**THE FIX IS PROVED BY MUTATION IN BOTH DIRECTIONS, and the second direction is the one that matters.** Reverting `sorting.html` to `cryPlayer.muted = true` fails three checks; making `#save()` write `#storedMuted || #viewMuted` again fails the same three. A negative case that only undoes the load path would leave the slider path unguarded, so the slider is now **exercised deliberately** in the cross-page section — nothing touched it before, which means the second gate had no test at all. Its wait is on `volume === 0.55`, the *other half of the same write*, so it proves the write **happened** rather than proving that nothing ran; polling for the absence being asserted would pass instantly on a page that never wrote at all.

**THE MEASUREMENT HAS TO DISTINGUISH "MUTED BY THE CHECKER" FROM "SILENT".** The tap zeroes `ctx.destination`, so `TAP_PROBE`'s own `gain` is 0 by construction. The player's level is read from `inGain` — one node upstream, the player's own gain — so "the checker muted the last centimetre" and "the page asked for nothing" are separate numbers rather than one. Expect this shape anywhere a test silences the thing under test: **discard the output, measure upstream of it.**

## Y. `cry-game.html` — 叫聲猜謎, And The Axis That Had To Be Measured Before It Could Be Written
Ported from `pokemoncries.com`. Ten questions a round, four nameless sprites each, one cry to listen to. **The design was measured twice and rejected twice; both rejections are the reason this section exists.**

- **THE NAME IS ONE HALF OF A PAIR, and the pair is why `color-game.html` is 顏色猜謎.** 叫聲猜謎 / 顏色猜謎 — four characters, one shared suffix, differing only in the medium. **This page's name is what made 猜謎遊戲 ambiguous**, so the naming rule and the rule about not renaming one of the four sites without the rest live in **§3.W**, not here. Read them before changing either title, `<h1>`, NAV label, or share string.

- **THE DIFFICULTY AXIS WAS RANK BANDS FIRST, AND 困難 AND 地獄 DID NOT SEPARATE.** The obvious encoding of 「how hard is this question」 is how similar the three distractors are to the answer. Rank bands over the neighbour list — 簡單 from the far half, 困難 from the near quartile, 地獄 the three nearest — read as obviously correct and are not. **Measured across all ten pools (all 1,025 plus each generation), `p90(困難) − p10(地獄)` was negative in every one: −0.093, −0.255, −0.186, −0.194, −0.204, −0.161, −0.204, −0.235, −0.262, −0.195.** Two of the three tiers were the same tier, and the only symptom would have been a difficulty tab that changes nothing a player can hear. **The reason is structural: with four options the answer competes against exactly three others, so a question's difficulty is its SINGLE hardest distractor — and three drawn at random from the near quartile put that one at rank ~21 of 256, which is almost as confusable as rank 3.** Expect this shape on any axis expressed as a window over a ranked list when the question consumes a fixed small number from it.

- **SO DIFFICULTY IS A CEILING ON ONE NUMBER.** Sort the neighbours, drop everything above the tier's limit, take the first three: `easy 0.35 · hard 0.65 · hell Infinity`. A question's difficulty is then the ceiling *by construction*, so `check_cry_game_similarity.mjs` asserts `hardestSim <= ceiling` per question as an **identity, not a tolerance** — the same comparison the module filters on. `Infinity` is not a special case anywhere: the filter is `sim <= ceiling`. The property that makes it shippable is measured, not argued: **across 10 pools × 3 tiers × 6,150 species checks, 0 ceiling violations and 0 degraded questions**, and measured hardest-distractor similarity is now **0.349 / 0.647 / 0.738–0.879** by pool, monotone and separated by ~0.30 and ~0.19 in all ten.

- **THE GENERATION FILTER IS A POOL, NOT A DIFFICULTY.** The reference's only axis was the generation, and it cannot be: Gen I has 151 members and Gen VI has 72, so 「第一世代」 and 「第六世代」 at the same distractor policy are not comparable rounds. It survives as a chip row, and its list is **derived from `availableGenerations()`** — a chip list and the pool filter that has to agree with it are one value, not two (§3.P).

- **ALL 34 DIMENSIONS, NOT cries.html's ROBUST FIVE.** Cosine over the standardised `ROBUST` five measures **0.996 at p50 for every pair** — five near-positive dimensions have no angular spread, so the metric saturates and no band is distinguishable. **Expect this shape on any cosine over very few correlated positive dimensions: it does not measure distance, it measures that everything is similar.** All 34 give a 3rd-nearest of p1 0.552 / p50 0.793 / p99 0.949. **`m0` is kept deliberately against §3.G1's `UNCOMPARABLE`** — its documented defect is that it moves with file length, which makes it a duration proxy, and two cries of the same length do sound alike. A dimension that is a defect when comparing two implementations of one analysis is signal when asking 「do these two sound alike」.

- **`cry-game.js` CONTAINS NO `Math.random` AT ALL.** `buildRound` and `eliminateIndex` default `rand` to `Math.random` and neither default is overridden, so the claim is *enforceable* rather than 「this page only reaches for randomness where the module allows」 — which is a shape a reader has to check by eye. The same reason `game-tips.js` is a module (§3.W).

- **THE NAMES ARE HIDDEN UNTIL THE ANSWER.** The reference prints the species name on all four cards, which makes the game 「remember which cry belongs to which name」 — unanswerable by anyone who has not memorised the dex, and nothing to do with recognition. Here a card is a picture and a number while the round plays. **§3.W's greyscale rule is deliberately NOT reversed**: there the sprite was a leak *beside* the clue; here it *is* the answer.

- **FOUR DEFECTS FOUND BY DRIVING THE PAGE, NONE OF THEM REACHABLE FROM A SHAPE ASSERTION.** `check_cry_game.mjs` had **134 assertions green throughout all four**:
  - **The round ended one question early.** `advance()` asked `indexOfCurrent + 1 >= length`, but writing the pick had already advanced `indexOfCurrent`. Answering question 9 of 10 closed the round: nine played, a result panel reading 「2 / 9」, a stored round with a trailing `null`. The reader now STAYS on the question they answered — which is also what they want, since they are reading the reveal.
  - **Saved picks restored as nothing.** `(saved.picks || [])[q]` indexed by the question *object*, which stringifies to `[object Object]`. Every pick came back `null`, the round silently restarted, and the picks were still validated against the rebuilt questions — so **a shape assertion cannot tell 「restored」 from 「reset to nothing」, because they are the same value.**
  - **`findIndex`'s -1 fell into the mid-round branch.** A finished round returns −1, and `−1 < MAX_QUESTIONS` is true, so `slice(0, -1)` dropped the tenth question and the board came back reading 「第 9 / 9 題」 on a round the reader had finished. **−1 is the ordinary answer for 「every element matched」, not an edge case to be swept up by an inequality.**
  - **The waveform was blank until the decode resolved.** Setting `canvas.width` clears it and `waveformPeaks()` is a fetch plus a decode: across a round driven as fast as a click allows, **four questions had ink and six had zero.** A flat placeholder is now drawn before the `await`.

- **§3.M IN BOTH DIRECTIONS, WHICH IS THE HALF THAT HAD NOT BEEN EXERCISED.** The usual reading is 「`hidden = true` does not hide it」 because an author `display` wins. This page shipped **the other one**: seven elements carry `hidden` in the markup, `setRevealed(el, true)` cleared only `style.display`, and the 下一題 button never appeared — because writing `style.display = ''` says nothing about an attribute the UA sheet is still acting on. `setRevealed()` now writes **both**, and the checker asserts exactly two writers of each.

- **THE HEADER MODIFIER WAS `header-cries`, WHICH IS NOT A CLASS ANYWHERE.** Invented from the group's name, and `check_cry_game.mjs` passed it because it asserted `used[0] === 'cries'` — a name the page happened to carry rather than whether `shared.css` defines it. The page rendered `.header` alone: the mobile column, nav on a second row, theme toggle in the corner. **`check_nav_pages.mjs` caught it on its next run, which is the argument for asserting MEMBERSHIP rather than restating a name.** Two of the three assertions guarding this were themselves wrong in ways that hid it: the list was read out of `assets/js/shared.js` (**JavaScript, which contains no selectors**, so the set was empty and the check reported 「not one of the 0」).

- **§3.A AT THE ONE PLACE A URL IS BUILT.** The answer's dossier link comes from `pokemonDetailUrl()` — which is what keeps `nidoran-f` and `nidoran-m` distinct — and the checker asserts a hand-assembled `detail.html?slug=` never appears. §3.I at the delegation: the four cards are re-rendered every question change, so the listener is on `#cg-choices` and reads the index off the card.

- **AUTOPLAY IS THE ONE FEATURE THAT CANNOT WORK ON THE FIRST QUESTION, and that is a browser rule rather than a choice.** Measured: `cryPlayer.play()` before the document has been activated leaves its promise **PENDING forever** — three seconds measured, no rejection, `onStart` never fires — because `unlock()` awaits `ctx.resume()` and Chrome holds that open until a gesture. So `maybeAutoPlay()` requires an `audioUnlocked` flag set by a one-shot **capture-phase** document listener calling `cryPlayer.unlock()` on the reader's first click of **any** kind, including a choice card. **The flag is load-bearing, not an optimisation**: without it the page calls a play that can only hang. Measured after a single card press — unawaited `play()` starts within 1.2 s with **no further gesture**, repeatedly. The switch is `cry-autoplay.js`'s `mountAutoplay` (§3.G: one preference, one default, one piece of markup) mounted as `className: 'cg-autoplay'`, so **every rule it needs lands in `cry-game.css` and not one in `cry.css`** — and it shares `pokemon-algorithm:cry-autoplay` with `cries.html`, `spectrum.html` and `cries-gen1.html`, which means a reader who turned it off there gets no surprise noise here.

- **THE RESULT PANEL LISTS ALL FORTY AND EVERY ONE PLAYS ITSELF.** The reference's result page makes all forty of its cards clickable, and that is the reason the block exists: playing the **distractors** is what lets a reader hear which of the four they were looking for, where a per-question button playing only the answer would say nothing the green border has not already said. **It is NOT a `<details>`** — §3.X measured `::details-content` inserting a box into the box tree, and the row label is a FIXED 44px because left to size itself 「第 10 題」 is wider than 「第 1 題」 and every row's first sprite shifts (measured after: **1 distinct x position across all 10 rows**).

- **`DEFAULT_GENERATION` IS A DEFAULT AND NOT AN OVERRIDE.** 簡單 opens on 第I世代, the other two on all 1,025 — the same relationship `game-similarity.js` has between its own `easy` and `hard`. **THE TWO AXES ARE INDEPENDENT, and that is what makes it safe:** measured over 600 questions, 地獄 on 第I世代 has a hardest distractor of p50 **0.879** against the full dex's **0.842** — a smaller pool means CLOSER neighbours, so 簡單's default is a gentler round without becoming a fourth difficulty. `state.genTouched` is persisted rather than inferred from the stored generation, because the two are indistinguishable afterwards, and it is set **before `setGeneration`'s early return** — on 簡單 the selected chip IS the default, so a reader clicking it to "confirm" would record no choice at all.

**Guarded by:** `check_cry_game_similarity.mjs` (177, ~3.2 s — re-measures the ceiling on every run, so a data change goes red instead of quietly becoming a threshold that still passes) + `test_check_cry_game_similarity.mjs` (31 cases, ~30 s), `check_cry_game.mjs` (134, 0.1 s) + `test_check_cry_game.mjs` (36 cases, 0.8 s). **There is NO browser checker for this page**, and the colour game has none either — §3.W's closing gap, still open. The four defects above were found by driving the page by hand, which is not a mechanism anything enforces. The page checker ends with a section that pins all four **by name**, so a *second* occurrence is at least caught by a shape assertion; the first one of each is still not.
