依 base cry 分組

38 個 base cry 共用於 151 隻。同一組內的叫聲只差在音高與長度兩個位元組上。

第一世代叫聲實驗室

紅／綠／藍的 151 隻叫聲並不是 151 段錄音。Game Freak 只寫了 38 段 base cry，其餘全部是用兩個位元組從這 38 段推導出來的：音高（0–255，直接加到 11 位元頻率暫存器上）與長度（−128…127，作為時間縮放乘數）。這一頁用瀏覽器的 Web Audio 重新合成它們，你可以改那兩個位元組，立刻聽到結果。

合成與聲道

聲道時間軸

三條聲道各跑各的。脈衝聲道的音符結束於自己的幀數；噪音聲道比較長時，它最後那段會在脈衝聲道結束之後繼續，而那正是音高偏移已被取消的地方。

這張表裡能算出來的東西

兩組完全相同的叫聲

噴火龍與獨角犀牛、蚊香蝌蚪與百變怪，base cry、音高、長度三個值完全相同 —— 合成出來的 PCM 是位元組相同的。

注意：獨角犀牛（Rhyhorn, #111）和鑽角犀獸（Rhyhon, #112）是兩隻不同的寶可夢。後者用的是 base 11，只和前者在音高與長度上相同、基底不同。中文資料常把這兩個名字混用，導致「噴火龍和鑽角犀獸同叫聲」的錯誤說法。

兩組幾乎相同的叫聲

綠毛蟲與角金魚共用 base 22，長度位元組分別是 0x20 與 0x40。第一脈衝聲道的長度因此差 —，Bulbapedia 記載為 0.071 秒。

腕力與菊石獸共用 base 31，音高分別是 0xEE 與 0xF0，頻率相差 —。

差異比想像中小：0.071 秒的長度差要靠 Bulbapedia 的數字才量得出來，音高差不到 1%。

音高偏移會把音符捲繞回最低頻

頻率暫存器只有 11 位元，音高是直接加上去的，超過 2047 就捲回接近 0。

蚊香蝌蚪與百變怪共享 base 0E，音高是 255（最大值），於是第一個音符落在 131,072 Hz —— 那不是聲音，是聽不到的超高頻。往後三個音符都溢出，各自捲到 66–510 Hz，結果是一聲低沉的轟鳴。

這個捲繞不是模擬的缺陷，而是文件記載的行為：較大的偏移可能讓結果比原音更低。當前選擇的物種有 — 個音符會捲繞。

為什麼有些叫聲尾巴會「崩潰」

噪音聲道的音高偏移在兩個脈衝聲道都結束之後被清除，而硬體並不檢查噪音聲道狀態。所以噪音聲道如果比脈衝聲道長，尾段會用原始參數播放，聽起來像突然的爆聲。

嘟嘟就是這樣。另一頭，蛋蛋的脈衝音符比較長，噪音聲道結束時偏移還沒被取消，所以牠沒有這個尾巴。當前選擇：—

151 隻、38 段、重製之後

第七世代之後每一隻都有自己專屬的叫聲，第一世代這種「同一段音樂反覆變調變速」的做法就消失了。這也是為什麼 Bulbapedia 說那些曾經相同的叫聲，現在已經不再相似。

對照：第二世代把基底擴充到 68 段，其中 30 段是新的，只有耿鬼與月亮伊布沿用第一世代的基底。

這一頁是怎麼合成的

Game Boy 的 CPU 跑在 1,048,576 Hz，這裡以 65,536 Hz 合成 —— 剛好是 1/16，沒有任何誤差，一個 59.7275 Hz 的音符幀正好 1090.67 個樣本。Web Audio 的取樣率上限是 96,000 Hz，所以無法直接用真實時脈。

代價是 32.768 kHz 以上的頻率全部遺失。Game Boy 的脈衝波是方波，方波的諧波延伸到無限遠，所以高頻噪聲會和真機有一點差異 —— 參考作者本人的網頁也標註了同一件事。音量包絡的每幀步進速率不在兩份上游說明裡，是模型而非實測，頁面控制台可調整。

出處

指令與數值來自 pret/pokered 的 data/pokemon/cries.asm 與 audio/sfx/，由本站的 scripts/fetch_gen1_cries.py 解析成 JSON。分組與相同叫聲的說法對照 Bulbapedia 的 Cry 頁，音訊格式的細節來自該頁引用的技術說明。

這裡的音訊是瀏覽器即時合成的，不是錄音。要聽原始錄音請看 叫聲總覽。
