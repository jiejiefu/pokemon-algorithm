## 1. Project Overview

**寶可夢演算法** is a static, zero-build HTML/CSS/JavaScript web application (GitHub Pages compatible) visualizing computer science algorithms and design tools using 1,025 Pokémon.

## 3. Key Technical Conventions & Invariants

### A. Routing & Slugs
- **Local & GitHub Pages URLs**: Internal navigation uses query parameters (`detail.html?slug=bulbasaur` or `color.html?slug=bulbasaur`).
- **Nidoran Disambiguation**:
  - `nidoran-f` (#029) and `nidoran-m` (#032) are distinct slugs.
  - A bare `nidoran` slug is strictly disallowed and must not resolve.
- **Form Links**: Alternate forms link back to their base species detail page.
- **detail ⇄ color Reciprocity**: `detail.html` and `color.html` link to each other (`單一色盤` ↔ `完整資料頁`), and both must build their cross-page URL from the one canonical helper — `pokemonDetailUrl()` in `shared.js` and `paletteUrl()` in `color-palette.js`. **Never assemble either URL by hand or by string-replacing `detail.html`** — `paletteUrl()`'s docblock gives the reason: `color.html` deliberately does *not* inherit detail's clean-URL contract, so the two shapes can diverge and a derived string breaks the day either gains a path segment. `detail.html` imports `paletteUrl` from `color-palette.js` for exactly this reason; that module has no top-level side effects, so the one-function import costs a parse and nothing else.

### B. Color Extraction & MMCQ System
- `assets/data/color_palettes.json` is generated by `scripts/extract_color_palettes_mmcq.py`:
  - 6-color MMCQ partition sampled from 96×96 front sprites (alpha ≥ 200).
  - **Pixel Snapping**: Synthetic MMCQ centroids are snapped to the most frequent real pixel in each bounding box.
  - **Frequency Share**: Shares represent global pixel frequencies across the sprite (sum < 100%, median ~71.95%).
  - **Short Palettes**: Exactly 3 palettes have 5 colors instead of 6 (#201 Unown, #643 Kartana, Bulbasaur shiny) due to sprite pixel limitations. Never pad these artificially.
- **Reference Project**: `pokemonpalette` is credited for color scales and UI concepts, while `color-thief` is credited for the palette algorithm.

### B1. The Generator Is Not a Smaller Report — `colors.html`

`colors.html` and `color.html` share `paletteGridHtml`, `paletteStripHtml`, `.cp-cell` and `.cp-strip`. That is a **shared component library, not a shared layout**: the pages differ in what they are *for*, and the difference is structural, so it must be maintained deliberately or the generator drifts back into being a duplicate.

| | `color.html` | `colors.html` |
| :--- | :--- | :--- |
| Verb | **reports** one species' measured palette | **generates** a theme from a colour you supply |
| First viewport | the species (450px artwork hero) | the **colour input** (the dial is the hero) |
| Measured palette | the subject, in three ramps and a showcase | **not rendered — one click away** |
| Shade ramp | three rows, one per top colour | **not rendered** |
| Shiny | a toggle, on-page | **not indexed at all** (see below) |

- **Five sections were DELETED, not merged: 「對照 · 實測色盤」, 「生成明暗階」, 「套用展示」, 「生成組成」 and 「匯出主題」.** All five belonged to overlapping concerns or duplication with `color.html`. Two copies of one species' palette is duplication, not comparison — and the first version of this section claimed the measured grid was "the differentiation that cannot exist on `color.html`", which was true of the *concept* and false of the *value*: by the time a reader reached it, `color.html` was one click away and the second copy was strictly worse. **This page's job ends at the generated palette.** The measured palette, the ramps, the showcase and theme tokens are `color.html`'s, and the provenance chip's whole job is to say where they went.
- **The ramp is not derived on `colors.html` anymore** — the export and tiles sections have been removed. `colors.html` no longer derives `generateTailwindScale(inputHex)` or ships `--cg-*` CSS variables; that responsibility belongs to `color.html`.
- **THE PAGE'S OWN COPY MUST NOT DESCRIBE WHAT WAS REMOVED.** The meta description and the intro paragraph both kept promising 「生成明暗階、套用展示」 and 「同時擺出生成與量測兩種東西」 after those sections were gone. A search-result summary and the first paragraph are the two places a reader is most likely to believe, and no shape check reads either.
- **Do not restore a removed section "just to be helpful".** `check_color_match.mjs` asserts the ABSENCE of `sec-measured` / `sec-gen-scale` / `sec-showcase` / `sec-gen-tiles` / `sec-export`, of their containers (`#scale`, `#showcase`, `#tiles`, `#theme-code`), of the leftover `showcaseHtml` / `themeCss` code, of buttons (`copy-theme`, `copy-json`), of the `.cg-measured` / `.cg-collapse` rules, and of any dangling `getElementById` target for them (`scale`, `tiles`, `themeCode`, etc.) — in both the use form (`els.scale`) and the declaration form, because a null key throws in exactly the same way one step later.
- **`color.html`'s shade scale is THREE ramps, the generator has none.** The report page takes the top **three** palette colours by share and derives an 11-step ramp from each, so the other measured colours are no longer bare swatches with nothing derived from them. **Each row is seeded from its OWN hex, and that is the whole reason the ★ is honest**: `generateTailwindScale` keeps its seed verbatim at the anchor step and the page marks that step, so three ramps all seeded from `primary` would render three credible rows with three ★s, every one marking a colour its row is not showing. Bulbasaur's three anchors land on steps **700 / 500 / 300**, so "★ = the primary" is not even true of the primary's own row any more — the page's prose says 「★ 標示的是該列色票本身」 instead, and that sentence is asserted. The row gutter is a 28px colour bar with **no text**: a `<button>`, because a colour chip's first instinct is to be copied, which is why it carries its own `aria-label`. 28px and not 22 — WCAG 2.2 SC 2.5.8 asks 24×24 of a target and a narrower bar clears it on height alone. `colors.html` renders no ramp at all — `.cp-scale` is untouched and `.cp-scale-stack` / `.cp-scale-row` / `.cp-scale-seed` belong to `color.html` alone.
- **Every element id is a named property of the document, so a bare `scale` in `color.html` is `<div id="scale">`.** This broke the showcase for real and it is the reason the guard below exists. Moving the ramps inside the row callback took `const { scale, anchor }` out of `render()`'s scope, and the showcase call's shorthand `scale,` then resolved to `window.scale` instead of throwing. A DOM node answers `scale['50']` as `undefined`, so `showcaseHtml`'s `scale[step] || primary` returned the primary for **every** step, which set `--cp-sf`, `--cp-ink` and `--cp-bd` all to one colour and drew 「色彩美學」 in the primary on a primary background. Silent, invisible, and in the one section whose entire job is to prove the palette is readable. The showcase now generates its own ramp from `primary` and names it `primaryScale`. **Expect this shape anywhere a page uses short ids** (`#scale`, `#q`, `#sort`): a missing `const` is not a `ReferenceError` when the document already owns the name, and a `Map`-style lookup on a DOM node answers `undefined` rather than throwing, so any `obj[key] || fallback` quietly becomes `fallback` for every key.
- **`generatedRows()` IS THE INPUT COLOUR PLUS THE MATCHED SPECIES' REAL COLOURS, and that is why the generated palette is anchored rather than invented.** It is not six shades of one guess: it is your colour, then the six colours the sprite measurably contains. The corollary, now that the measured grid is gone, is that **the generated palette IS the measurement** whenever the input happens to be that species' primary — which is the default landing state, since the page opens on Bulbasaur's primary. That is the coincidence that used to need `#cg-collapse` to explain itself, and the deletion resolved it rather than documenting it.
- **`assets/css/colors-generator.css` exists so this page's rules are not `color.html`'s problem.** Every rule in it is `cg-`-prefixed and mounted only here; it is the reverse of the arrangement `colors.css` documents ("page shell inline, components in colors.css"), which exists because three colour pages share components. Putting generator-only rules in `colors.css` couples three pages to one. **Never edit an existing `.cp-*`, `.sc-*` or shared token for a generator-only need — add a `cg-` rule.**
- **The 24-cell legendary grid is a NAMED entry point, and it pins the species — not just the colour.** `LEGENDS` in `colors.html` is `[id, edition]` pairs only; the name comes from `pokemon_data.json`, because a second copy of an official name is a second thing to keep right. 8 across × 3 rows, because 8 is what fits 1,180px at ~130px a cell, and the hero's 380px left column fits nothing.
  - **Loading only the colour and re-running the matcher answers the wrong question.** `#FFFFFF` is the primary of **29** species, so the rank-1 result for white is #0278 and clicking 萊希拉姆 would present a Wingull's palette under a card that says Reshiram. A tie is not the same as an absence: the matcher is right and the answer is still wrong, because "closest" was never asked. `matchOf(id, hex)` therefore builds the record for a named species, with `rank: -1` — a pin did not win a competition.
  - **The winner card's eyebrow is the honest part, and it depends on how the species was chosen.** 最接近 for a ranker's pick, **你選的** for a reader's, plus a tie notice reading 「這個主色有 N 隻共用，排名不由它決定」 from `primaryShareCount()`. Labelling a rank-29 pin 最接近 would be a false claim on the page's largest type.
  - **A pin survives re-ranking ONLY while the input is still one of that species' own six colours.** An unconditional exemption is wrong the other way: click 萊希拉姆 then type `#00ff00` and you keep seeing Groudon. The species' own palette is the exception because the 「換一個生成起點」 row feeds those in one at a time.
  - **The grid is built ONCE, in `init()`, and only its highlight moves.** Calling `renderPresets()` from `render()` threw away 24 buttons and re-requested 24 sprites on every keystroke to change one class — and, worse, left every reference pointing at detached nodes, which do not bubble to the delegated `document` handler, so the control went dead after first use.
  - **Two of the 24 have a near-white primary** (萊希拉姆 `#FFFFFF` 36.5%, 索爾迦雷歐 `#FBF7EE` 37.8%) and the page says so under the grid. They are there because a cover Pokémon is a cover Pokémon; dropping the two that flattered the page would be curating the evidence.
- **The colour field speaks three notations, and the toggle is DISPLAY ONLY.** HEX / RGB / HSL. `parseColorInput()` accepts all three regardless of which is showing, so pasting `rgb(57, 148, 148)` out of a stylesheet works on the HEX setting; a toggle that filtered input would split the typed path from the paste path. `inputFormat` never round-trips through the text, because `formatHex(hex,'hsl')` rounds to whole numbers and `#399494` reads out as `hsl(180,44%,40%)` and back as **`#399393`** — flipping the toggle would restate the colour and every number on the page would then describe one the reader never chose. The hex is the single stored value.
  - **THREE states, not two.** Parseable → commit. **A possible prefix** → say nothing (`hsl(18` is the fourth keystroke of a colour, not a mistake). Neither → flag it and LEAVE THE PREVIOUS RESULT ON SCREEN. `couldBePrefix()` is what keeps the error from scolding per keystroke.
  - **Ranges are strict, never clamped.** `rgb(300,0,0)` is a typo; clamping it to `rgb(255,0,0)` answers a different question.
  - **The format note is LIVE and appears only on error.** It shows the current colour in the two notations the reader is *not* using, so the thing to copy is the thing on screen. It was a static paragraph first, which said a true thing nobody needed until they were already stuck.
  - `parseColorInput()` and `pinSurvivesRequery()` are page-local — §3.B1 forbids adding them to `color-palette.js`'s exports — so `check_color_match.mjs` **lifts them out of the source and runs them** against the real corpus. A source-shape regex over the same lines passes for any mutation that leaves the substrings in place, which is how the first version of the pin guard was blind.
- **The error colour was a hardcoded `#ff9b9f`, and it failed in the light theme.** 8.72:1 on the dark grounds, **1.72:1** on the light `--bg-controls` — a pale pink on a pale blue-grey, invisible in every screenshot taken in dark mode. Now `var(--error-text)`, which shared.css already themes (`#ff7a85` dark = 7.00:1, `#b3261e` light = **5.57:1**). The checker computes both ratios rather than reading the declaration.
- **`#cg-winner` had no `class` attribute, so `display: flex` never applied** and the sprite, strip and text stacked vertically for the life of the page. Nothing about that is visible to a shape check — the elements existed and carried the right classes. Pinned explicitly.
- **The sprite and the strip are side by side inside one `flex: none` figure.** As siblings of the card their width was decided by the species NAME, so the strip was 168px for 無極汰那 and 60px for 夢幻. A caption that changes size with its neighbour is not a caption.
- **`assets/js/color-match.js` never adds to `color-palette.js`'s export surface.** Three pages import that file; the matcher is imported by exactly one. It also does no DOM, no fetch and no audio, which is the only reason its claims are checkable.

**Shiny palettes are deliberately NOT in the match index.** A shiny palette is the same creature recoloured, not a different creature, so indexing both lets one Pokémon enter under two identities and the reader cannot see why it outranked the others. Measured on 3,872 probes of the sRGB cube, **58.2% of winners would have been shiny** — so this is not cosmetic, it changes more than half of all answers. Shiny belongs to `color.html`'s toggle, which is a same-page comparison; this page ranks across species. The cost is real and measured rather than waved away: excluding shiny raises the match distance by **median +0.0026, p95 +0.041, max +0.076** (`#00ff00` resolves to #167 at 0.0894 instead of shiny #140 at 0.0844).

**The distance is OKLab ΔE, and that choice is load-bearing.** §3.B2 records `findClosestChineseColorName()` returning 墨綠 for `#414141` because nearest-in-RGB let a table entry 8 away in one channel beat every grey 20 away in all three. That table was 100 names; this searches 6,148 sprite colours, 61× more. Measured: plain RGB Euclidean and the redmean approximation disagree on the **winner** for 12.8% of a 576-point cube sweep, and on the whole top five for 83.2%. Two further traps the checker pins, both found by writing the mutation and watching the obvious assertion survive:
  - **`#ffffff has L = 1` cannot detect a wrong transfer function.** 1.0 is 1.0 however it is decoded; a swap to plain gamma 2.2 passes it. The assertion that works is **mid-grey**: `#808080` reads 0.599871 and gamma 2.2 reads 0.603241, against a 1e-4 tolerance.
  - **A greys-vs-tinted pair cannot detect a dropped chroma axis either.** With `a` and `b` zeroed every colour lands on the lightness axis, and a grey still beats a dark green, because `#414141` (L 0.3753) really is nearer `#3a3a3a` (L 0.3485) than `#0b3d0b` (L 0.3159). The detector is a **saturated red's chroma coordinates**, which no axis-only metric can produce. Expect this shape: the check that reads like the guard is not the guard.
- **Ranking is primary-first, secondary-as-tiebreak, then ascending id**, and every one of those three is a claim with a wrong version that returns a plausible list. Primary-first rarely bites — **6 of 4,545 corpus colours (0.13%)** have a non-primary nearer than the winner's own primary, and `#20317b` → #970 is pinned as one that does. It is a correctness statement, not a tuning knob. The id tiebreak is what makes `#ffffff` reproducible: it is the primary of **29** species, all at distance exactly 0, and 222 of the 1,025 palettes contain it somewhere.
- **There is no "too far to match" threshold**, deliberately: 6,148 colours cover enough of the cube that any input has an answer, and a threshold is lying to the user occasionally. The ΔE number is displayed instead, on the winner card.
- `node scripts/check_color_match.mjs` (220 checks) and `node scripts/test_check_color_match.mjs` (28 mutation cases) guard it. **Seven of the twenty-eight cases named the wrong assertion when first written and every one was blind** — the RGB swap (it multiplied OKLab coordinates by 255, a change of *units*, which cannot reorder anything), the gamma 2.2 swap, the dropped chroma rows, the reversed tiebreak chain, the reordered palette rows, and two count assertions. The §4 table is the right place to add this suite's entries.

### B2. Colour Naming — Three Namers, One Chroma Gate

The pages do not use one colour namer, they use **three**, and `color.html` prints two of them **side by side for the same hex**: the prose at `color.html:589` is `describeHex(primary)` and the swatch list at `color.html:577` is `chineseColorName(hex)`. Before the gate below they disagreed on **97.6% of primary colours**, and the disagreement was not two words for one colour — each was separately wrong about greys. Arceus #493 was the visible one: primary `#e6e6ee` at 35.73% is 230/230/238, so max−min = **8 of 255**, a grey. `describeHex()` read hue 240 and lightness 91.8 and never looked at saturation, so it said **淺藍**; `chineseColorName()` ran a 100-entry nearest-neighbour over RGB and landed on **薰衣草紫** (`#E6E6FA`, 12 away in one channel). The page said both.

**Every namer is gated on `chroma()` = max−min of the three channels, below `NEUTRAL_CHROMA = 16` → `neutralName()`** (黑/深灰/灰色/淺灰/灰白 by lightness). Measured on all 12,297 corpus swatches: `describeHex` renamed 1,620 (13.2%), `chineseColorName` 2,387 (19.4%), `colorTemperature` 178 (now all `neutral`), and **0 chromatic swatches changed** — the gate sits below the coloured cluster.

Four things here are load-bearing and each was measured rather than assumed:

- **Chroma is absolute and must never be HSL saturation.** `s` is a ratio against lightness, so `#fffff6` measures **s = 100%** while being nine channels from grey, and near-whites are the largest single grey bucket in the corpus (白: 698 of the 2,387). Refactor the gate onto `s` and every near-white flips from grey to a loud colour name. `#e6e6ee` is the mirror image at s = 19%. `chroma()` has two pinned values and one `isNeutral('#fffff6')` assertion for exactly this.
- **The threshold is in a gap, not merely low.** The corpus chroma histogram is empty between the grey cluster and the coloured one, so **16 through 31 all behave identically**; 32 is where it starts eating. That is why raising it cannot be caught by a "greys are named greys" check — nothing between 16 and 32 changes. Of 709 distinct hexes under 16, only 24 have `s >= 40` and every one is a near-white, so nothing visibly tinted is demoted.
- **`describeHex()` on a pure grey returned 紅, not 白.** `max === min` leaves `h` at 0, which is the first bucket in `hueNames`. This is why 1,510 of 12,297 (12.3%) were mis-named before, and it is the checker's most direct detector.
- **Nearest-in-RGB will always match a grey to a tinted name**, because an entry 8 away in one channel beats every 淺灰 that is 20 away in all three: `#414141` came back **墨綠**. 351 of the 2,387 sub-threshold swatches were named this way.

**`灰白` exists because 白色 would be a false claim.** `#e6e6ee` is 92% lightness and is not `#ffffff`; the highest band above 淺灰 is 灰白 and the `l > 0.93` branch keeps real whites white.

**`chineseColorNameWithEn()` is gated identically and deliberately returns the zh-only grey name** — pairing 灰白 with *Lavender* would assert the exact claim being corrected. It is on no colour page today, which is precisely why it needs its own case: an unpaired gate there is invisible until someone imports it.

`check_color_palettes.mjs` guards all of the above, and `test_check_color_palettes.mjs` adds **9 mutation cases against a scratch copy of the module** (the 11 pre-existing cases mutate the palette *data*, which cannot reach this code at all). The scratch tree copies all of `assets/js` because `color-palette.js` → `shared.js` reaches five more files, and a case failing on "cannot find module `form-names.js`" passes for the wrong reason — the baseline case is what proves the harness sound.

**Expect this shape when a guard can only be satisfied vacuously.** Raising `NEUTRAL_CHROMA` to 255 satisfies all three "must not be chromatic" assertions *and* the demotion check at once, because with the threshold at 255 there are **no chromatic swatches left** and the demotion check counts zero. The detector has to be an assertion about colours that ARE still chromatic — here four pinned names (`深藍`/`綠`/`黃`/`青`) beside the threshold. One case was declared as the demotion check and had to be repointed after measuring that it was blind.

### C. Contrast & Accessibility Rules
- **Color Contrast (WCAG AA)**: Minimum 4.5:1 for standard text, 3:1 for large text and UI components.
- **Measurement Method**: Verify contrast by sampling decoded screenshot pixels via Canvas/CDP, not via `getComputedStyle()` (which misses alpha blending, backdrop filters, and radial gradients).
- **Typography**: CJK-first font stack in `--font-sans` (`PingFang TC`, `Noto Sans TC`, `Microsoft JhengHei`) to avoid mismatched English/Chinese rendering.
- **Theme Switching**: Handled inline in `<head>` before first paint to prevent flashes. Toggling triggers a `themechange` event for Canvas redraws.
- **Reduced Motion**: Honored across CSS and JavaScript. Sprites snap immediately to target coordinates instead of lerping.

### D. Type Profiles & Scoped Translations

InfoPoke publishes **no zh-TW catalogue** for this route — its own zh-TW pages render raw i18n keys — so the file mixes three provenances and they are kept in separate fields rather than merged:

### F. Cry Audio & the Generation I Table
Two independent sources, two independent sets of traps. Neither may be hand-edited; both are generated and both are checked.

**`assets/js/cry-index.js` (generated by `scripts/extract_cry_index.py`)** rosters `assets/cries/`, a byte-for-byte copy of [PokeAPI/cries](https://github.com/PokeAPI/cries). No re-encode, no rename — what plays is exactly what played when the page fetched it from `raw.githubusercontent.com`.

- `latest/` holds 1,351 files and covers all 1,025 species; the 326 unclaimed `10000+` form files are counted and reported but kept out of the roster, on the same rule as §3.E. `legacy/` holds 649 files, the older Gen 1-5 recordings.
- **93 files under `latest/` are not Ogg despite the extension** — 92 are MPEG layer III and one is a WAV. Only ids **25, 808, 809** are roster species; the other 90 are form files. So `Content-Type: audio/ogg` on `25.ogg` is a lie the browser never sees: `decodeAudioData` sniffs content rather than trusting the header, and `canPlayType` cannot be trusted to detect them at all. The checker magic-sniffs all 1,674 roster files rather than reading extensions.
- **Every legacy file differs from its latest counterpart — 649 of 649, byte for byte.** "Old recording" is the entire reason `legacy/` exists; a copy backfill would silently retire it, so the checker compares all 649 pairs.
- **Peaks exceed 1.0.** `25.ogg` decodes to a maximum sample of 1.0391, so any envelope built by sampling raw float data must clamp or it draws outside the canvas.
- `node scripts/check_cry_index.mjs` (50 checks) and `node scripts/test_check_cry_index.mjs` (21 mutation cases) guard it. Four of those cases failed when first written and each was a real hole, not a bad expectation — worth reading before trusting any assertion here that "looks obviously true".

**`assets/data/gen1_cries.json` + `gen1_cry_sfx.json` (generated by `scripts/fetch_gen1_cries.py`)** parse [pret/pokered](https://github.com/pret/pokered)'s `data/pokemon/cries.asm` and 114 `audio/sfx/cry{NN}_{1,2,3}.asm`. The `.asm` files are **build-time inputs and are not vendored**; they mirror into the gitignored `data-sources/pokered-cry/` when `test_check_gen1_cries.mjs` needs them.

- **The table is unordered from its first row.** All 151 species sit at a position that is not their dex id, by up to 174 places; row 1 is Rhyhon (id 112). So every id in the JSON can only have come from the `; Name` comment — a positional join would hand Bulbasaur Rhyhon's cry. `test_check_gen1_cries.mjs` **shuffles the rows and requires the regenerated JSON to be byte-identical**, which is the only thing that actually proves it; a comment cannot.
- **The join key has two hazards in it.** Punctuation differs (`Mr.Mime` upstream, `Mr. Mime` in `pokemon_data.json`), so punctuation is dropped; but Nidoran♀ (29) and Nidoran♂ (32) differ *only* by a gender symbol, so symbols are transliterated (`♀`→`f`, `♂`→`m`) rather than dropped. Getting either backwards merges two species onto one key, which is why an ambiguous key is a hard error and never a coin flip.
- **38 base cries, not 114 files.** Upstream ships each base three times as three link entries for one sound; the copies carry identical commands and differ only in the `_1`/`_2`/`_3` inside their labels — including inside cry0d's `sound_loop` target, which is why loop targets are stored as `"Ch5"` and not as literal labels. The fetcher stops the build if the replicas ever diverge, and `check_gen1_cries.mjs` re-asserts it.
- **Case is the whole filename trap.** Constants are uppercase hex (`SFX_CRY_1A`), filenames are lowercase (`cry1a_1.asm`). A case-sloppy map looks right for the ten all-digit bases and 404s for the other twenty-eight.
- **Upstream is not self-consistent, and the checker must not be.** `cry02_1.asm` uses the older single-value `duty_cycle` (expanded to four repeats on parse); the volume sweep is a signed nibble written both ways (`noise_note 13, 1, -1, 124`); `cry06_1.asm`'s Ch6 is an empty channel; and **six** of the 114 channels have no `sound_ret` at all — recorded in `implicitRet` and asserted as an exact set, because "at most six" would pass both when the parser drops commands and when upstream fixes one. Never assert something upstream does not do.
- `node scripts/check_gen1_cries.mjs` (40 checks) and `node scripts/test_check_gen1_cries.mjs` (23 mutation cases plus the shuffle proof) guard it.

**`assets/js/gb-apu.js`** re-synthesises those 38 base cries, so `cries-gen1.html` plays the cries rather than loading them. It is a pure module with no DOM, no Web Audio and no fetch, which is the only reason the claims below are checkable at all.

**It is verified against the reference's own OUTPUT, not against a description of it.** `assets/data/gen1_conformance.json` holds, for all 151 species, the output length plus 48 sampled values of the 8-bit form the reference page's Download button produces — generated by driving that page in headless Chrome, not by reading its source. The checker also re-imports the APU at 1,048,576 Hz to produce those renders, since Web Audio's ceiling is why the page uses 65,536.

*This distinction is the single most important thing in this section.* Six bugs had this APU confidently disagreeing with the reference while **agreeing with every other file in the project**, because every assertion compared it to a *description* — and a description can be wrong in ways that are self-consistent. Nothing short of comparing output found any of them. Current result: all 151 lengths match exactly, 98.7% of sampled values are byte-identical, every remaining one within one 8-bit step.

**The comparison is 48 samples per species, and that is deliberate.** It used to be 48 samples plus one full-file byte-compare: `assets/data/gen1_charizard_ref.raw`, the reference's complete 1,000,692-byte download for #006. Nothing read it. `check_gen1_apu.mjs` only ever opened the three JSON tables, `gb-apu.js` and `cries-gen1.html`, so the file was copied into all 36 mutation fixtures — about 36 MB of pointless I/O — while AGENTS.md described a byte comparison that had not existed for some time. That is the §4 failure shape exactly: a claim nothing was checking, written down so precisely that it read as verified. The file is gone; the 151 × 48 comparison is what runs, and what the numbers above describe. Regenerating a whole-file vector would mean a 1 MB tracked artifact per species change, which is the cost the sampled form exists to avoid.

- **The length parameter is the stored byte MINUS `0x80`, not its two's-complement signed reading.** The reference's slider holds `byte - 0x80` and the multiplier is `+0x100`. Reading the byte as signed gives a multiplier `0x80` larger, which makes every note **1.5× too long**. Charizard stores `0x80`, so its parameter is `0` and its multiplier `0x100` — no stretch at all; the byte-as-signed reading makes it `0x180`. Its sampled vector settles it: the lengths stop matching.
- **The duty register holds the PACKED byte, not the pattern array.** The reference reads it as `duty & 3`, so an array coerces to `NaN` and then to `0` — silently selecting the 12.5% window on every note of every channel whose low two bits are not `00`. Charizard's second pulse channel is duty `$5A`, low bits `2`, so that channel played inverted for the entire cry. The two channels whose low bits happened to be `0` matched by luck, which is what made this look like tuning rather than a bug.
- **The mix is NOT peak-normalised.** Three channels at a third each sum to at most 1.0, so the signal cannot clip; normalising only rescaled every cry, made a soloed channel as loud as a full one, and made comparison against the reference impossible.
- **Every register is in samples at the Game Boy's clock, so each must be scaled to the output rate — including the noise LFSR clock, which was not.** The pulse channel's `period` was; the noise channel's was not, so at 65,536 Hz the LFSR ran once per 512 *output* samples: 128 Hz where the hardware means 2,048. The symptom was a cry that was correct in every respect except that it had **no hiss in it**. Measured on the rendered channel, 76 zero crossings per second against the reference's 1,533; after the fix, 1,532.
- **…and that is precisely what a native-rate conformance comparison is blind to.** At 1,048,576 Hz the conversion factor is exactly 1 and the bug is a no-op. Comparing at the native rate is what makes every length and every waveform sample verifiable, and it is exactly the rate at which a rate-dependent bug disappears. So the checks for it are **rate-independent by construction**: the same species must report the same noise clocks and render the same grain at 65,536 and at 1,048,576. Expect this shape again — a quantity that only matters on the way to the speakers can only be checked on the way to the speakers. The master volume was the other one, and **it has been removed rather than checked**: `sliderToMaster()` mapped a 0..10 page slider onto the channel scale's 0..15, which made the default reading of 3 a master volume of 5 — a third of full scale, too loud — and it was a conversion between two numbers that were already the same unit, so there was nothing for it to be right about. The page now presents 0..15 directly and defaults to 3, and the claim is asserted **by measuring** rather than by reading an expression, because it is still the one loudness quantity no waveform assertion can reach.
- **The duty register turns once per FRAME** (upstream's own comment says "once per frame"), and the volume envelope steps once per `|sweep|` frames. Charizard's first three notes sit at RMS 0.3125, 0.2849, 0.2708 — each slightly lower because of its own fade, with no collapse inside a note.
- **`sound_loop` IS applied**, and the reference's feature list marking it "unsupported" refers to its UI, not its data: cry0d's Ch5 arrives there with the block already duplicated, 14 entries where the raw table holds 7. `count` is the number of TIMES the block plays. Dropping it left the nine species on base cry0d short by exactly one block.
- **The one sound_loop's `target` and `count` are the only fields used**, so loop targets are stored as `"Ch5"` and not as literal labels.
- **Note positions are accumulated in clock units and rounded once**, not per note: the reference's `17,556 × frames` is an integer at its own rate, and rounding each note's delta instead of the cumulative position lost 4 samples across Charizard.
- **The pitch-shift cancellation is per note, not per sample**, and the offset is decided at the note's start against a cutoff one frame before the pulses are *scheduled* to end — the sum of the notes, not the length they render to, since the ring-out runs on past it. Measured over the corpus: of 689 noise notes, 620 keep the offset, 69 begin after the cutoff and never get one, and **63 span it**, so for those the pitch changes partway through. `noiseOffset()` is the single definition both the renderer and the timeline call, after they each carried their own copy and disagreed on every note (one in samples, one in seconds).
- **The ring-out is bounded only where the envelope can never empty.** Upstream does not implement `sound_ret`, so its last note rings until the volume reaches zero; a sweep of `0` means it never does, and an unbounded version rang one synthetic note for four million samples. Sixteen frames is the bound there. Bounding *every* note is wrong and was: a legitimate tail is up to fifteen envelope steps each a whole `|sweep|` frames apart, so 240 frames at the largest sweep, and a flat 16-frame cap silently truncated seven species by one frame each. **Those seven were then recorded in the checker as a "known set" on the reasoning that a tolerance beat a red test** — which was covering up a bound that would equally have hidden a truncation twice as large. Do not do that: a named exception list is for upstream quirks you cannot fix, never for your own truncation.
- **The data is diffed against the reference's own command tables**, and it is byte-identical across all 38 bases — every `frames`, `volume`, `sweep`, `freq` and `duty` byte in all 114 channels. That diff found the one remaining data bug: `fetch_gen1_cries.py` read the fade as an unsigned literal, while the tables use a **4-bit signed magnitude** (`pokered`'s macro packs the direction into bit 7 and notes that "a value of 8 is the same as a negative one"), so `square_note 12, 0, 8, 0` means *increase*. Stored as `+8` it is a fade out of a note whose volume is 0, which clamps at 0 and makes the note **silent** — nine notes across six bases. pokered's own engine agrees, writing `$8` to NR12 with the comment "fade in sound". The checker asserts the **range** `[-8, +7]`, not the nine values, so the next one is caught whatever it is.
- **The synthesis rate is 65,536 Hz, not the real 1,048,576 Hz**, because Web Audio caps a buffer at 96,000. The ratio is exactly 1/16, so nothing drifts.

`node scripts/check_gen1_apu.mjs` (92 checks) and `node scripts/test_check_gen1_apu.mjs` (39 mutation cases) guard it. Sixteen of those cases failed when first written and **every one was a real gap rather than a bad expectation** — the mutation test is the reason this section exists, so read it before trusting any assertion here that "looks obviously true". **The harness is not in `check_all.mjs`'s manifest any more**, so a green default run is not evidence that it would still catch anything; §3.G5 has the reasoning and the guard that stands in for it, weakly.

**The mutation harness had the disease this section warns about, and the rule now lives in §4.** A case's `expect` must name the assertion that actually detects its mutation; four of the 34 did not, and every one of them passed for an accidental reason because the matcher asked only whether the text appeared *anywhere* in the checker's output — and a checker prints an assertion's description whether it passes or fails. The worst of them had been calling itself a timeline test for its whole life while being a waveform test. `scripts/lib/negative.mjs` now decides this for all ten negative suites, and §4 has the full table of what each case was actually detected by.


**Where the 39 cases' time goes, and the two structural fixes.** 17 of them need the conformance loop and 22 do not — the split is decided by `CONFORMANCE_EXPECTS`, and getting that polarity backwards is what this paragraph used to do. The checker's native-rate conformance loop is **4.8 s of its 6.5 s**, so:

- The corpus is walked **once**, not four times. Four separate loops each rendered all 151 species and two measured the same thing; `renderSpeciesCry` is pure in `(cries, sfx, id)` with no options, so one pass answers all four questions. The per-species result is reduced to scalars and **dropped** — retaining 151 renders would hold ~78 MB of Float32Array alive, which is the one way this edit could cost more than it saves. Checker: 6.5 s → 5.5 s, and its output is unchanged line for line.
- The 22 cases whose detector is *not* the conformance comparison run against a fixture whose **copy** of the checker has that section removed: 5.5 s → 0.63 s each. `scripts/check_gen1_apu.mjs` gains no switch and no environment variable, because a supported way to skip the conformance comparison is how it would stop happening; the baseline always runs the whole checker. Eligibility is decided by `expect` alone, so there is no per-case flag to forget and an unflagged case runs everything.
- The one guard that makes the strip safe: the baseline runs a **second** time with the section removed and requires it to pass having dropped **exactly 4** of the 92 checks. A strip that took one check too many would leave the 22 cheap cases asserting against a silently narrower checker, and every one of them would still pass — they only require their own detector, which a narrower checker satisfies more easily, not less. **Nothing may live inside the stripped region that reads the repository**, because a fixture is not the file: an audit first written here compared the harness's 39 `expect` strings against the *stripped* copy, could not find the assertions 17 of them name, emitted 17 failures, and broke this very assertion. It now lives in `check_all.mjs`, which is not a fixture.
- Measured on this machine at `POOL = 4`: **~62 s → ~34 s**, with all 39 cases and all 92 checks intact. Cheapest first is wrong — the heavy cases are issued up front, so every trailing wave is short.

**Generating the conformance vectors has one trap worth writing down.** The reference's roster is a **0-indexed array**, so a dex id is `index + 1`. Reading it as `pokemon[id]` shifts every vector by one species and produces a plausible-looking file that matches nothing — including one species whose vector is not a species at all. The checker therefore asserts the two rosters agree on cry, pitch and length for all 150 before it trusts any of the audio, and the vectors carry those three fields for exactly that reason.

### G. The Two Cry Pages

`cries-gen1.html` and `cries.html` are driven over the Chrome DevTools Protocol by `scripts/check_gen1_page.mjs` (74 checks) and `scripts/check_cries_browser.mjs` (25 checks). Those exist because they are the claims no static checker can make — `check_gen1_apu.mjs` can prove the synthesis is right, but not that the page says true things about it or that pressing play does anything.

- **A playback cursor's guard must be `!== null`, never `> 0`.** `AudioContext.currentTime` reads exactly `0` on the first play, because the context has only just resumed, so `startedAt > 0` reported "not started" for the entire first playback and the cursor simply never appeared. Both pages draw one, from one clock, so the waveform's played region and the timeline's playhead cannot drift.
- **The waveform is cached in an offscreen canvas** and playing costs one `drawImage`. It is a thousand-odd line segments plus labels, none of which change while audio plays. The cache is bound with `const` from the first line — there is no "get the visible context, then reassign it to the cache" step, which is how `cries.html` ended up throwing a TypeError instead of drawing anything (below).
- **`cryPlayer.play()` resolves when a cry ENDS**, so a caller had no way to know when playback began or how long it would run. It takes an additive `onStart` hook carrying the duration and the clock reading; the player owns the AudioContext and is the only thing that can read that clock.
- **Both cry pages share ONE autoplay switch, and it must never fire on load.** `assets/js/cry-autoplay.js` mounts a `role="switch"` control with `aria-checked`, ON by default and persisted under its own localStorage key — one module rather than two copies that would drift apart invisibly. It is ON by default because both pages exist to be skimmed: comparing two species means clicking a chip and listening. **The rule that matters is the load case, and it takes a different shape on each page.** `cries-gen1.html`'s `select()` runs at boot, on every hashchange and from the reset button as well as from a chip, so there the switch is a *parameter* (`autoplay: autoplay.on`) and only the click handler passes it. `cries.html` reads the switch inside `probe()`, which is only ever reached from two click handlers — so the check there is on the call sites, and `check_cries_page.mjs` counts them on comment-stripped source: a fourth mention lives in a comment, and matching prose would make the count change when the code is explained. Expect this shape: on a page where one function serves boot and clicks alike, the feature flag has to be an argument rather than a read.
- **A mute nothing verifies is not a mute, so the second line is installed in the page.** Both CDP checkers keep `--mute-audio`, and that flag is the right *first* line — it mutes at the browser, so the AudioContext still runs and `currentTime` still advances, which is what keeps the playback assertions meaningful. It is not the whole guarantee, because it is a request: a mute that quietly stops working produces no red output, only a cry at a fifth of full scale, which is the worst pair of failure modes available. So `scripts/lib/mute-tap.mjs` is injected with `Page.addScriptToEvaluateOnNewDocument` — before any page script, so the module scope cannot race it — and replaces `AudioContext.destination` with a gain node at zero. Both pages wire their output through exactly that one call (`cry-player.js:196`, `cries-gen1.html:279`), so nothing reaches the speakers.
  - **Nothing either checker reads is downstream of that gain.** `currentTime`, `startedAt`, `duration`, `aria-pressed` and canvas pixels are all clock or DOM. The APU still renders every sample and `resume()` is still what unblocks the clock, so "pressing play reaches the synthesiser and moves a cursor" is still precisely what is measured. Only the last centimetre is discarded.
  - **And it is asserted, by reading the live `AudioParam` rather than a value recorded at install time** — so the question answered is "is the output muted *now*", and a page that opened the tap back up is caught. The probe sits **after the first play**, because the AudioContext is built lazily and a probe before that reads a tap that has not been asked to do anything. Verified by mutating the module in a scratch copy: `FAIL ... (0 AudioContext(s), gain null, the tap script never ran)` and `FAIL ... (1 AudioContext(s), gain 1)`. A mute that fails loudly is a mute; this one used to fail silently.
  - **One module, not two copies** — for the reason `cry-autoplay.js` is one module. Two copies of a mute drift invisibly, and the drift is noise.
  - **The limit, named:** it wraps `window.AudioContext`, so it does not cover `OfflineAudioContext` (which has no output device to mute anyway) or a page that reached the audio hardware another way. Neither page does.
- Both also take `CRY_PORT` (default 5500) so they can run against whichever Live Server port is actually up.
- **Never assert that an idle control is showing live state.** The timeline lane label read 播放中 for every unmuted channel, which was never true of anything.
- **A `details` group must stay open when it holds the current species.** Selecting a Pokémon used to collapse the list it had just been picked from, so comparing two relatives meant reopening the same group for every click.
- **The stored length byte is the frame count minus one.** Printing it as a frame count made every note in the command list read one frame short. The list shows the real count with the raw byte beside it, since the byte is what the ROM stores.
- **Count drawn pixels by ALPHA, and the assertion must be able to return false.** `cries.html`'s `drawWave()` bound its context with `const` and then reassigned it to the offscreen cache two lines later, which is a TypeError in module scope — the probe waveform never drew at all. `check_cries_browser.mjs` reported `ok` for the entire time, because it counted "dark" pixels in the top four rows while ignoring alpha, so every untouched pixel `(0,0,0,0)` scored as dark (2,400 of them, a perfect score), and because it asserted `typeof drew === 'number'`, which is true of `undefined` and therefore of no result whatsoever. It now measures ink across the whole canvas and requires more than 500 of it. Expect this shape on any canvas check: **a blank canvas is transparent, so alpha is the only thing that distinguishes "drew nothing" from "drew black".**
- **A slider's id is not the state field's name.** The three sliders were wired `for (const id of ['pitch','length','volume']) state[id] = value`, which worked for two of them and silently created a fourth property for the third: the Length slider's key is `lengthSigned`. Expect this shape: a control can be inert and there is nothing in a screenshot to notice.

The consequences were silent — the promise REJECTED instead of resolving on `ended`, `onStart` never ran, and `#overlapping` stayed empty so `stop()` could not silence the voices it had layered. Asserting on settlement is the one thing the swallowed rejection could not hide. **A stub rather than a page is the determinism**, because Live Server reloads whenever a concurrent session writes a file, and a test whose subject is "does this promise resolve" must not depend on whether anybody is editing; `fetch()` is stubbed by path because the player asks for a relative url only a page can resolve.
- **Its mutant must be written OUTSIDE the repo, or `--prove-inputs` fails both ways.** The mutation case copies `cry-player.js` next to `cry-index.js` so the mutant's own `import './cry-index.js'` resolves, and it used to do that in `.cache/cry-overlap-neg/`, on the reasoning that "a temp directory outside the repo cannot resolve a relative import" — true of the mutant alone, false of the mutant plus its one import (`cry-index.js` imports nothing itself). Inside the repo those scratch reads are real reads of real paths, so `--prove-inputs` reported them **read but not declared**; and declaring them is not the fix either, because the same proof then fails the other way on **a glob that matches nothing** once the directory is deleted. The recorder ignores anything outside ROOT (`scripts/lib/record-inputs.cjs:106`), so a `mkdtempSync` makes this entry's input list **exact** rather than hand-maintained. It is the one entry in `cry-page` that is neither a page check nor a mutation harness.
- **The recorded cries play at the SAME loudness as the synthesised ones.** `cry-player.js` exports `DEFAULT_VOLUME = 3 / 15` and it is the default in *both* localStorage branches and the field initialiser. It was unity, and pressing play on `cries.html` or `detail.html` was genuinely startling — a recorded cry is a plucked square-ish tone with a wide dynamic range, and comparing twenty of them at full scale is not something to ask of anyone. It is 3/15 specifically because that is the master volume the Generation I lab presents as its default, so the two pages can be compared without one being louder for reasons that have nothing to do with the Pokémon. It lives in the **player** because the player owns the output gain; a page-level trim would have to be written twice and one page would eventually be missed. The per-call `volume` argument in `play()` is a separate per-play trim and still defaults to **1** — it multiplies into the shared gain, so defaulting it to the same number would square the level to 0.04.
- **The three sliders' rows must be pinned, not bottom-aligned.** `align-items: flex-end` aligns the one edge that differs: the hint under each slider is one or two lines of 10px text and they do not come out even, so 長度 was pushed up while 音高 and 音量 were pushed down — three labels at three heights. Each `.cg-slider` is therefore its own grid with `grid-template-rows: 20px auto 1fr`: the label always gets the same height, so the labels share a baseline and the tracks share a line, and the hint — the only part that varies — hangs below freely. The range also gets an explicit `height: 22px`, because an unstyled range's default height differs per engine and 2px there moves the whole track.
- **The intro's 6:4 split must leave the prose column AT LEAST its own measure.** The paragraph is set to 68ch, so a split that narrows the column below that does not change the line breaks — it just makes the grid the binding constraint and leaves the measure a lie written in the stylesheet. 7:3 gives ~700px at this page's width, well past 571px of measure, so the extra room buys nothing and costs the sprite its share; 6:4 lands at 590px. `check_gen1_page.mjs` asserts the column is not narrower than the measure, and reads the **grid tracks** rather than the sprite figure's box — `justify-self: center` shrinks that box to its 112px of content, so measuring it reports a 9:1 split for a grid set to 6:4.
- **The waveform ink is not the accent.** `--accent-gold` is gold in dark and **Poké Ball red** in light — by design, per shared.css's own comment on the light palette. Right for a link or a 3px outline, wrong for a 120px trace, where at ~4,000 points a red trace stops being a waveform and reads as one solid block. The traces and the playhead therefore use `--cy-wave-ink` (the gold in dark, a slate mixed from `--text-primary` and `--bg-card` in light); the **note bars keep the accent**, because the unshifted-tail marker has to stay a different colour from its parent bar and that difference is the load-bearing part of the crash explanation. Both values are theme tokens, so the no-raw-hex rule still holds.
- **The mix's sample count was printing seconds.** `${samples.length / SYNTH_RATE | 0} 個樣本` floors a sub-second cry to zero, so that line read **"0 個樣本" for all 151 species**. And it is now printed with a thousands separator, which broke the check that reads it — matching `\d+` against "62,541 個樣本" captures **"541"**, a different number that still scaled correctly with the slider, so nothing downstream could tell.
- **The four waveforms are four ROWS OF ONE STAFF, not a waveform above a timeline.** `cries-gen1.html` draws `mix / pulse1 / pulse2 / noise` the way the reference does — one band each, sharing a time axis — and each band carries its own note bars underneath its trace. Two reasons, and the second is the load-bearing one: **a waveform's horizontal extent *is* a timeline's extent** (same `total`, same interval), so drawing it twice as two stacked blocks asked the reader to hold an alignment in their head that the page could guarantee for them. One row per channel cannot disagree with itself. The mix is row 0 of the **same grid**, not a separate canvas above it — that is what makes all four share a left edge and a width, and a checker asserts the mix is `.cg-lane-mix`'s plot rather than a sibling of the staff.
- **Draw a trace, not a min/max envelope.** The reference draws a polyline through the samples, one point every four, and that is the only reason its lanes read as waveforms. A per-column min/max cannot show a Game Boy square wave at all: at 65,536 samples over ~700 columns a column holds ~87 samples and contains **both** extremes, so every column spans the full height and the lane comes out as a solid bar. Following the samples has a second benefit — a flat run needs no special case, because the noise LFSR shifts only every 128 samples, so most of that lane is a plateau and a plateau drawn as a line is a visible horizontal line. The envelope version needed a one-pixel branch for exactly that and still came out 96% blank (173 inked pixels of 34,656).
- **The lane traces hang from the bottom of their band, not centred in it.** The negative excursion is given up on purpose: a symmetric trace uses the band twice over and reads as a filled block, whereas hanging it frees the lower half for the note bars, so a lane reads as *sound above, notes below*. The low level is not discarded — it is the line on the zero line, so a square wave shows its two levels, which is the duty cycle the command list prints as a percentage.
- **Every one of the six synthesis bugs above was found by comparing against rgmechex's OWN OUTPUT, and that is the page to thank.** [rgmechex.com/tech/gen1cries.html](https://rgmechex.com/tech/gen1cries.html) is the reference synthesiser; `gb-apu.js` is transcribed from its source rather than reasoned about, and the six documented failures (per-quarter-period duty rotation, continuously-decaying envelope, time-stretched noise, single-field noise rate, no ring-out, byte-minus-0x80 length parameter) were each written wrong first and each only surfaced against that page's output. **This is recorded here rather than on `cries-gen1.html` on purpose:** the page's 出處 section names the reference and the behaviours taken from it, which is what a reader needs, and the story of our own debugging is not theirs to read.
- **A waveform must be drawn at full scale even when the audio is quiet.** The APU multiplies the mix by `clampVolume(volume)/15`, so at the default of 3 the array the page holds is a fifth of full scale — and the mix was drawn from it directly, so the whole thing looked like a whisper *and changed shape as the reader dragged the volume slider*. `unmasterGain()` inverts the APU's own factor; loudness belongs in the ears, a waveform is a picture of the sound's shape. A master volume of 0 renders all zeros, and that lane says 音量 0 rather than drawing a flat line, which would be a different and wrong claim (「this Pokémon is silent」).
- **Two axes in one row: bars are positioned in SECONDS, the waveform is indexed by SAMPLES.** Dividing a note's start by the sample count puts every bar under 0.02% of a 62,541-sample lane — seven bars stacked on the left edge, and a check that only counted them saw nothing wrong. `check_gen1_page.mjs` reads the last bar's right edge, the one number that moves when the two are conflated.
- **A muted lane changes colour rather than only opacity**, because gold at 0.28 alpha over a dark panel is still gold, so the dimming communicated nothing. Measured as a colour distance between two lanes, since "it looks dimmer" is not something a checker can be asked about.
- **The picker's 151 sprites are asserted as a BINDING, not as a download count.** All 151 chips are `loading="lazy"` and the panel is long, so a few seconds in only some 50 have decoded. An earlier version of the check asserted "every sprite in the viewport has decoded" and failed — that measures Live Server's throughput, not the page, and the only way to satisfy it would be to delete the lazy loading that is correct. What is checked instead: every chip has a sprite, each one's `src` is **its own species'** file rather than a shared placeholder, all are lazy, and the one image the reader is looking at — the selected species' — decodes at 96px, which is the only failure mode the binding can have.
- **A clock read every frame and written nowhere is the same bug as a dead slider.** `cries.html`'s probe cursor computed `(progress.now - progress.startedAt) / progress.duration`, and `progress.now` was initialised to 0 and never assigned again — so the ratio was negative, clamped to 0, and the cursor sat at the origin for the life of the page. `cry-player.js` now exports `now()`, because the AudioContext is private to the player and a page cannot fake that clock on a different timebase without drifting against the `startedAt` it was handed. Two instances of this shape on one page, which is the tell: **a field that is read but never written is a feature that was never built.**
- **The probe waveform's played region is painted in the Pokémon's own colour**, not with a dark wash. The wash is the Generation I lab's device and it reads as "already played" only because that trace is gold on a dark panel; on a neutral slate it is a dirty smear that says nothing about *which* Pokémon is sounding. So `drawWave()` keeps the trace as **geometry** as well as pixels — a 220-segment `Float32Array` — and `blitProbe()` re-strokes the played part over the neutral one, in the sprite's average `rgb` (the same value detail.html puts on its hero card). **The accent keeps BOTH endpoints of every envelope segment** — `probeTrace` is four numbers per sample (x, top, bottom), not two. It was two, holding only the top, and the played region drew as a single line along the upper envelope: playback showed the top half of every bar and nothing below it, which is not the same waveform in another colour but half a waveform. The accent also strokes at the **same weight** as the neutral trace, because a heavier accent made the played half a different-looking shape rather than the same shape recoloured. `check_cries_browser.mjs` counts the accent's ink either side of the zero line for exactly this reason.
- **A checker that presses play must CONFIRM the press landed, because a detached node makes a click a silent no-op.** `check_cries_browser.mjs` captured the probe's play button once and clicked it 140 ms later — and autoplay is ON by default (§3.G), so the cry already sounding ended in between, and `renderProbe()` writes `#probe-play`'s `innerHTML` on every play and every stop (`cries.html:496`). The captured node was **detached**, a detached node does not bubble to the delegated listener on `#probe-play` (`cries.html:812`), and the click did nothing: 60 samples over 1.28 s read `aria-pressed=false` and zero accent pixels, every time. Nothing noticed, because **the measurement did not require playback** — the scan loop's first sample landed inside the *autoplay's* final frames, so the reported `maxX` was wherever that unrelated playback happened to be. It surfaced as a flake (`x=669` idle, `x=696` under load, one green and one red across a 5%-wide band straddling the 95% threshold) and would have been "fixed" by widening the tolerance, which is the trap: **a control bug wearing a tolerance's clothes.** The button is re-queried at every use, the press is retried until `aria-pressed` flips, and `pressing play starts playback` is now its own assertion — the one whose absence let 19 green checks measure a click that never fired. Expect this shape wherever a page re-renders a control's markup: the same failure is documented in §3.B1 for `colors.html`'s preset grid.
- **Which frame an assertion reads decides whether it is a measurement or a coin flip.** The played-region checks now take two frames: the **fullest** (most accent ink — the last frame painted before the cursor clears) carries presence, left-anchoring and above/below-the-zero-line, where more ink is strictly better evidence; the **earliest** (first frame carrying any accent) carries "the far end is still unplayed". On the fullest frame the playhead is at the end of the cry, so its rightmost accent pixel lands at 92-97% of the width and whether that clears a 95% bar is a matter of where the final `requestAnimationFrame` fell — measured at `maxX` 685/704/716/719/722 across five runs. On the earliest frame ~96% of the canvas is unplayed, and the value is now **4-23 against a limit of 686**: identical on an idle machine and under eight `yes` processes, which is what "load-independent" has to mean. The early `n > 400` break the loop used to end on had to go — it stopped sampling a few columns in, which would leave both frames the same and make the far-end claim vacuous.
**The two regions are drawn as two DISJOINT regions, not one over the other** — the cache is blitted only into the unplayed span and the accent stroked only into the played one. Stroking the accent on top does not work on this waveform specifically: it is a peak envelope, 220 vertical segments from each sample's top to its bottom, so at this width consecutive segments merge into solid bars and a 2px accent on the same path as the 1px neutral line puts the neutral line **down the middle** of the accent. All that shows is a tan fringe either side of a white core, which is exactly what "it looks like it is behind the grey" was. Because nothing overlaps, the accent can be as heavy as it needs to be to read at all. `check_cries_browser.mjs` locates the accent by colour **derived from that species' rgb**, not by comparing two thirds of the canvas: at the frame the loop stops on, the played region is a sliver, so a thirds-based mean compares two neutral bands and finds nothing. Its first version also wrote the predicate as channel tests tuned for a reddish accent, which excluded Charizard's tan exactly — so build the predicate from the colour you are looking for.
- **A filter and a scroll position are different quantities and must not share a field.** `cries.html` had one `state.gen` serving as both the generation filter and the page counter, so `render()` sliced `state.gen * PAGE_SIZE`: 第 1 世代 asked for 60 cards out of all 1,025 and showed exactly what the unfiltered page showed, with `aria-pressed` claiming the chip was on, and the sentinel's `state.gen++` re-picked a generation on every scroll. It is now `state.gen` (filter, narrowed by the pokemon record's own `generation`) plus `state.pages` (batches on screen), and `computeAxisRange()` reads the filtered set too — otherwise the meters stayed scaled against all 1,025 while the cards showed one generation.
- **The master volume is on the channel scale's own 0..15, and the page presents that same 0..15 slider, defaulting to 3** — about a fifth of full scale, which is comfortable where 15 is not. `sliderToMaster()` is gone, per the rate-independence note above. `check_gen1_apu.mjs` renders species 6 at volume 3 and at volume 15 and requires the peaks to stand in a ratio of one fifth: the mix divides by three and never normalises, so a ratio of peaks **is** a ratio of volumes. Note which mutation that actually catches — squaring the curve, which stays in range and leaves every waveform byte identical. The obvious one, `/ 15` to `/ 10`, is caught by the clipping check instead, because a full-scale render then exceeds 1.0; a case must name the assertion that detects it.

**`assets/data/cry_features.json` (generated by `scripts/analyze_cries.py`)** is one 34-number row per roster file — `dur` `peak` `rms` `zcr` `centroid` `rolloff85` `flatness` `flux`, then 13 MFCC means and 13 MFCC standard deviations — for 1,025 latest and 649 legacy cries. 499 KB, and no similarity matrix: 1,025² floats is 4 MB, and the browser multiplies the rows it already has.

- **Every file is resampled to 16 kHz first, and that is not cosmetic.** The corpus spans **fifteen sample rates**, 8,000–48,000 Hz, with 784 files at 32,728 Hz against 120 at 44,100 Hz. A mel filterbank built over each file's own Nyquist gives those two groups different meanings for the same coefficient, so a search would partly rank which encoder produced the file. 16 kHz is justified by measurement: 90.6% of energy is below 4 kHz and 98.2% below 8 kHz.
- **`peak` and `rms` are measured on the decoded signal, not after resampling**, because both are independent of sample rate and FFT resampling smooths `25.ogg`'s peak down from 1.0391 to under 0.94 — which would hide the fact that the corpus is not clipped. The measured maximum is 1.2111. Consumers drawing an envelope clamp at draw time.
- **legacy and latest are NOT comparable.** Centroid medians are 1,327 Hz against 2,992 Hz, flatness differs by two orders of magnitude, every legacy file is at 10,512 Hz. That is a difference in how the two sets were recorded, not between the Pokémon. They are stored under separate keys, range-checked separately, and the checker asserts the offset is *still present* so a change that quietly merged them is noticed.
- **`node scripts/check_cry_features.mjs` (24 checks)** and `node scripts/test_check_cry_features.mjs` (19 mutation cases) guard it. The assertion that earns its keep is **every dimension must vary across the corpus**: a constant column means a filterbank that collapsed or a DCT that never ran, which passes every shape and NaN check while the search degrades to chance.
- **"Most similar cry" cannot be a similarity ranking here.** Measured within one corpus: same-family pairs average 0.2076 against 0.0075 for unrelated pairs — a real separation — but top-1 same-family accuracy is **2.1%** against a ~0.1% random baseline. Log-mel mean+std (26/40 bands), MFCC 13, MFCC 20 and a 40 ms window all land between 1.5% and 2.1%; nothing is meaningfully better, because each modern cry was composed independently and evolutionary relation does not predict how a Pokémon sounds. These features are honest timbre descriptors. Present them as axes, not as a semantic ranking.
- `cries.html` therefore ships the search as a **音色** ranking with the measured figures on screen — top-1 2.1%, top-20 12.6% against a 3.2% baseline — and says 音色而非血緣 in the DOM. Two consequences worth knowing before editing it, both found by measurement rather than by reading:
  - **Scores must be standardised per dimension before they are compared.** Raw, `centroid` runs to 3,167 while `flatness` runs to 0.7, so an unstandardised cosine returns **1.000 for every pair** and the list looks perfectly plausible while being decided by two dimensions. `indexSet()` computes means and deviations **per set**, not once, because the two recordings differ enough that a legacy vector standardised with latest's statistics is not the same measurement.
  - **No weight preset may activate a single dimension.** Cosine over a 1-D vector is always ±1, so a preset called 「只看明亮度」 returns 1.000 for every neighbour and orders them by distance *descending* — the exact opposite of its label, silently. Ordering by one axis is what the sort dropdown is for. `similarTo()` still falls back to absolute distance if only one dimension is ever active, because that failure is silent rather than loud. `check_cries_page.mjs` asserts both.
- `node scripts/check_cries_page.mjs` (64 checks) and `node scripts/test_check_cries_page.mjs` (35 mutation cases) guard the page's claims. Five of those cases failed when first written and each was a weak assertion rather than a bad expectation: a `key:` regex that matched the weight presets as well as the axes, a `cp-` scan that found the comment explaining why `cries.css` must not claim one, a roster-gate check that tested for the identifiers instead of the import, a hardcoded-row detector whose threshold also flagged the probe's legitimate `[0, 1, 2, 3]` MFCC readout, and a `state.gen` write-count that balanced because the `IntersectionObserver` it was supposed to exclude is defined *after* the handler — so a mutation moving the sentinel onto the filter passed. The last two are the §4 rule in its purest form: the count has to be a count of something that cannot be on both sides, and the forbidden region has to be bounded at the thing that actually commits the sin.

### G1. The Spectrum Page — a Port That Is Checked Against Its Own Extractor

`spectrum.html` draws a mel spectrogram of any cry in the corpus, in all three sources at once: the 1,025 latest recordings, the 649 legacy ones, and the 151 Generation I syntheses re-rendered through `gb-apu.js`. It is a separate page because it answers a different question from `cries.html` — that one is a browsable index, this one is an instrument — for the same reason §3.B1 splits `colors.html` from `color.html`, and `cries.css` is already shared by two pages, so the new rules live in `spectrum.css` and every one is `sp-`.

**NO SPECTROGRAM IS STORED.** The band is already inside the repo: `analyze_cries.py` computes 26 mel bands per cry to get its MFCC, so the spectrum it describes is one function away. A stored bank would be 1,025 × 64 × 26 bytes, ~2.3 MB once base64'd, and would go stale the moment a cry was re-encoded. Recomputing one cry on demand is ~80 frames of 512-point FFT. The second reason is that a port can be **checked against the thing it ports**; a stored image is a claim, this is a measurement that carries its own error bar onto the page.

**`assets/js/cry-spectrogram.js` IS A PORT OF `analyze_cries.py`, and `check_spectrogram_port.mjs` (55 checks) differences the two on a synthetic signal both can synthesise from arithmetic alone.** "I read the Python and wrote the JavaScript carefully" is not evidence. The checker runs the extractor's *own imported functions* against this module's, and the tolerances are grounded in measurements rather than in the observed number.

**`analyze_cries.py`'s `resample()` has TWO BUGS, and they are recorded here rather than fixed, because fixing them moves the stored table.** Both are load-bearing for what the page may claim:

  - **Amplitude.** It multiplies the kept bins by `n_out / n_fft` before the inverse transform. Zero-padding a signal to `n_fft` does not change `X` — the transform is just sampled on a finer grid — so `irfft(X, n_fft)` returns `x` exactly and the amplitude-preserving scale is **1.0**. The proof needs no argument about spectral content: **a 100 Hz tone resampled from 32,728 Hz to 16 kHz comes back at 0.1465 of its amplitude**, and no Nyquist cut can be responsible for a 100 Hz tone. Measured over fifteen source rates and durations, `scale = 1.0` holds a tone to within 0.4% while `n_out / n_fft` loses between 15% and 95%.
  - **Cutoff.** It keeps `n_out / 2` bins of an `n_fft`-point transform, and those bins are spaced `sr_in / n_fft` apart, so its top kept bin sits at `(n_out/2) · sr_in / n_fft` Hz — 4,102 Hz for a 0.7 s signal, against the 8,000 Hz a resample to 16 kHz must keep. **`n_fft` follows the file's DURATION, so the cutoff does too**: measured across the 1,025 latest cries it lands between about 4.4 kHz and 8 kHz. Every stored row therefore describes a signal band-limited at a frequency that depends on how long the file is.

What that costs was measured, over 23 species spanning every source rate and both ends of the duration range: **31 of the 34 features have a median relative difference of `0.00e+00`**, with a worst of 1.5e-1 on `m2` and `m12` and only on the cries carrying real energy near 8 kHz. The wrong cutoff turns out to be cheap because the cries barely use the top of the band — the same fact `analyze_cries.py` cites when it picks 16 kHz. **`m0` alone moves systematically**, by exactly `log(n_out / n_fft) · √26`, because DCT row 0 is `√(1/26)` in all 26 entries while every row above zero sums its basis to nothing and cannot see a constant at all. Across the corpus that factor spans 1.741 in natural log, which is **8.88 in `m0` units against a stored spread of 37.58** — so roughly a quarter of `m0`'s variance is a function of how long the file is, and `cries.html` standardises `m0` before its similarity search.

**The module does NOT copy either bug.** It uses scale 1.0 and the correct Nyquist, because a spectrogram whose dB axis is 15–95% low and whose top octave is rolled off at a duration-dependent frequency is not a picture of the file. It exports `UNCOMPARABLE = [peak, rms, m0]` and `M0_SCALE_OFFSET = √26`, and the checker asserts the m0 relationship as an **IDENTITY rather than a tolerance** — satisfied by exactly one relationship between the two numbers, where a wrong filterbank, hop or window moves the observed value by whole units. A tolerance would have been satisfied by a mutation whose own difference is under 5%, and one of the negative cases is that mutation.

**`UNCOMPARABLE` HAS TWO CAUSES, and the page says so in two sentences.** `peak` and `rms` are a *limit of the browser*: they are measured on the signal at its true source rate, which is unrecoverable because `decodeAudioData` resamples to the AudioContext's rate first (§3.F, `cry-player.js` point 3). `m0` is a *defect upstream*. Conflating them tells a reader to distrust a tool when the tool is right, so the panel names all three and gives both reasons.

**THE PAGE REPORTS FIVE FEATURES AND NOT A RELATIVE DIFFERENCE FOR THE OTHER 29, and that was measured rather than chosen for taste.** Decoding `latest/1.ogg` at its own 32,728 Hz — so no resampling happens at all — the browser and `cry_features.json` differ by a **median 5.5%** across the 31 comparable features and by **1,181%** on the worst. That worst is an `ms` column: a standard deviation of MFCC values whose stored magnitude is about 0.002. Thirteen of the 34 are like that, and a relative difference on them reports a large disagreement about a number that is nearly zero. At the 48 kHz device rate the same file is **27%** off on the median and 27% off on the centroid, because that adds `decodeAudioData`'s own resample on top of the decoder difference. So the page prints absolute differences for the five that are both large in magnitude and well conditioned — `dur`, `zcr`, `centroid`, `rolloff85`, `flux`, whose relative differences are 0, 0.0005%, 3.6%, 2.7% and 0.22%. **`flatness` was in that set on the reasoning that it is a ratio bounded by 1 and therefore stable, and measured 31%.** It is scale-invariant and ill-conditioned — the geometric over the arithmetic mean, a ratio of two nearly equal numbers — and being inside `[0,1]` says nothing about how sensitive it is. That is the second time in this project a property which sounds like a guarantee turned out to be an unrelated one, and `check_spectrum_page.mjs` asserts its absence.

**A LIVE CURVE IS A SECOND MEASUREMENT, AND THE CAPTION SAYS SO.** The `AnalyserNode` tap hangs off the shared gain node (so a mute silences the measurement too, which is a true reading rather than a defect) and returns 1024 **linear** bins at the **device** rate over a 2,048-point window with smoothing 0.3 — about 42.7 ms against the offline 25 ms with none. Folding those into the same 26 mel bands approximates the offline path rather than reproducing it. It is on the page because it answers "where is the energy *right now*" at 60 frames a second, which an offline grid cannot do at all, and the caption names all three differences rather than letting one reading cover them.

**THE REVEAL IS NOT A STREAMING ANALYSIS, and the intro says so.** The whole spectrogram is computed before the reader presses play; playback uncovers it left to right at the AudioContext's own clock, so it is one set of pixels moving, not a second measurement. The axes are drawn *after* the veil rather than before, or the frequency labels would dim with the data and the reader would lose the one thing that does not change during playback. The unplayed region is veiled with the plot's own ground colour and not a neutral wash, because on a near-black ground a grey veil reads as a second data series. Under `prefers-reduced-motion` there is no veil and no playhead at all: the plot is the measurement and the wipe is only time passing.

**The plot is NEAREST-NEIGHBOUR on both axes, and the blockiness IS the resolution.** The horizontal axis is time on a fixed 10 ms hop, so a 0.18 s cry — the shortest in the corpus — really does put ~55 pixels between two measurements, and smoothing across them would draw a curve the analysis never made. The colour ramp is declared once in `spectrum.css` as `--sp-0`…`--sp-5` and read back with `getPropertyValue` into a 256-entry LUT, because the legend gradient is built from the same six custom properties and two copies of six hexes is two things to keep right. **The ramp is deliberately theme-INDEPENDENT** — dark means quiet in both themes — because re-mapping a colour scale per theme would mean the same number in the same cell reading as two different things, which is the one thing a scale must never do. What changes per theme is everything around it.

**`cry-player.js` gained three ADDITIVE methods and no behaviour changed.** `decoded()` shares the existing `#cache` so the page does not fetch and decode a second time; `playSamples()` exists so the Generation I synthesis plays through the *same* AudioContext, clock, gain and analyser as the recordings, which is what lets a reader put a synthesised cry and a recorded one in the same spectrogram; and `spectrum()` reads the live tap. The `decimate-by-two` fallback is load-bearing rather than defensive, because 65,536 Hz is the rate the synthesis arrives at and that allocation is what browsers refuse. `mountAutoplay()` gained a `className` option so a third page can share the one module instead of copying it — **one module, three prefixes, zero copied markup**, for the reason §3.G gives for the mute.

**`node scripts/check_spectrogram_port.mjs` (55 checks), `node scripts/test_check_spectrogram_port.mjs` (11 cases), `node scripts/check_spectrum_page.mjs` (87 checks), `node scripts/test_check_spectrum_page.mjs` (21 cases) and `node scripts/check_spectrum_browser.mjs` (43 checks) guard it.** The port's negative suite includes the two bugs above, deliberately copied in, and a periodic-Hamming-window case that **only the log-mel grid identity catches** — the 34 numbers are means and standard deviations over 68 frames, so a small per-frame error cancels out of them and is still visible in the cells. Three of its cases named the wrong detector when first written, which is §4 arriving from a new direction: a case that names an assertion which happens to be tripped for an unrelated reason is not a case. `check_spectrum_page.mjs` compares the module's constants to the extractor's **by value**, evaluating `SR = 16_000` and `int(round(0.025 · SR))` rather than pattern-matching them, because a regex that matched bare digits would have "compared" all nine constants while checking one.

**A LOADER ERROR IS NOT A TEST FAILURE, AND TWO PLACES HERE PROVED IT.** The port checker's subprocess resolves `../.venv/bin/python` relative to itself, so a `mkdtemp` in `/tmp` has no `../.venv`: the checker prints its SKIP line, exits 0, and every negative case would report FAIL having run zero assertions. The negative suite therefore places its trees beside a **symlinked venv**, and its baseline case is what proves the tree is sound. The other is `--prove-inputs` reporting `analyze_cries.py`, `shared.js`, `gb-apu.js` and `gen1_cries.json` as "declared but not read" — correct, since the page fetches those in the browser and the checker only saw its own imports. Rather than delete the entries, **each became a claim**: the extractor is read to assert the nine constants are declared at module level, `shared.js` to assert NAV carries the page, `gb-apu.js` to assert `SYNTH_RATE` is 65,536, `gen1_cries.json` to assert all 151 rows carry the two bytes `renderSpeciesCry` needs. A declared input nothing opens is an input whose edit will not invalidate the checker.

### G2. The Header Is Not One Thing — Two Silent Failures, Both From Writing Markup the Runtime Owns

Two defects in `spectrum.html`'s header produced a **visibly broken page with no console output, no failed request and no exception** — the two worst failure modes available, because nothing in §4's harness could see either one. Both are now guarded in `check_nav_pages.mjs` with negative cases, and both have the same root cause: **the header's contents are owned by `shared.js` at runtime, so hand-written markup in those containers is not a style question but a duplication question.**

**A BARE `class="header"` IS NOT A MISSING-STYLE PAGE — IT IS A VALID CLASS THAT RENDERS THE COLUMN LAYOUT.** `shared.css`'s base `.header` is `flex-direction: column` with `gap: 10px` (shared.css:428). The row layout every page actually renders comes from a **separate** rule listing six modifier classes (shared.css:1237) — `.header-dex, .header-3d, .header-colors, .header-detail, .header-sort, .header-maze` — which supply `flex-direction: row`, `gap: 20px` and `padding-right: 62px` for the absolutely-positioned theme toggle. So a page carrying only `class="header"` falls through to the column layout and every other nav check passes on it. Measured on `spectrum.html` at 1400×900 before the fix: the header grew **55px → 98px**, the nav dropped to **y=59** on a row of its own, its right edge landed at **1380** against a theme toggle starting at **1350**, and the two overlapped. `spectrum.html` was the **only** page in the project without a modifier. The fix is one attribute — `header-colors`, the group its two sibling cry pages use — and the guard **reads the six names out of `shared.css` rather than restating them**, because a hardcoded copy is a second thing to keep right and would keep passing after the stylesheet renamed one. The check also asserts the list is non-empty: if the row rule is ever removed, the guard has nothing to compare against and would pass on every page. **Expect this shape whenever a base class is the mobile/narrow layout and a modifier supplies the desktop one** — a bare base class is a valid, rendering, wrong page, and "it inherits from the shared header" is exactly the reasoning that lets it through.

**THE THEME TOGGLE'S OWN ICONS ARE INJECTED, AND THE RUNTIME'S GUARD IS THE TRAP.** `initThemeToggle()` adds its sun/moon pair only `if (!btn.querySelector('.icon-sun'))` (shared.js:614). A page that hardcodes a **differently-classed** pair therefore satisfies nothing: the guard is still true, the canonical pair is injected *as well*, and the button ends up with **four children in a 34px grid box**. `spectrum.html` had two `<svg class="theme-icon theme-icon-dark">` / `-light` beside the injected `icon-sun` / `icon-moon`, and **no stylesheet has any `.theme-icon` rule**, so both hand-written ones stayed `display: block` in BOTH themes while the injected pair toggled correctly — **three visible symbols**, with the third 18px icon at **y=49 inside a button whose bottom edge is y=46**, painting outside it. The button's ARIA label, role and click handler were all correct, so nothing about the control's *behaviour* was wrong. The fix is to leave the button **empty** and let the runtime own its contents, exactly as the nav container is left empty. Expect this shape on any container whose runtime fill is guarded by a *name* check: the guard exists to prevent duplication, and a differently-named duplicate is precisely what it cannot see.

**Both claims live in `check_nav_pages.mjs` rather than `check_color_page.mjs`** because that file already owns the mount-point claims — exactly one `<nav data-nav>`, exactly one `[data-nav-toggle]`, exactly one `[data-nav-drawer]`, and no page hand-writing `<a>` inside the nav container. The theme-toggle claim is the same disease in a different container, and it was found the same way: a rendered defect with a clean console. Its negative case must target a page that **actually has a toggle** (spectrum.html), and the row-modifier case must use the exact string `class="header header-colors"` — both anchors are load-bearing, and a stale one throws rather than passing silently, which is why this suite has a stale-anchor guard at all.

### G3. Race Mode — Six Lanes, and the One Shape That Renders Nothing

`sorting.html`'s 競速 tab runs 2–6 algorithms side by side on the same seeded shuffle. It shipped with **every lane blank**, and the cause is the same family as §3.B1's bare `scale` and §3.G2's hand-written header icons: **a bare name that resolves to the module's variable instead of the caller's.**

- **`paint()`, `ring()` and `sweep()` all closed over the module-level `ctx`**, which is the SINGLE-mode canvas. `frameRace()` cleared `lane.ctx` and then called `paint()`, which drew 130 sprites a frame into a canvas `setMode()` had set `hidden` — so every lane was cleared 60×/sec and nothing was ever drawn on it. **No exception, no failed request, no console output.** Only a screenshot or a canvas pixel count sees it; every shape check passes.
- **`sweep(progress)` took a parameter and then tested the module-level `sweepAt`**, so a lane's own `lane.sweepAt` was read by nobody and the finish wipe could only ever appear on the single-mode canvas. All three helpers now take the context and the timestamp from the caller, and `sweep()` returns whether it is *still running* so the caller clears its own field — reaching back to zero a variable it no longer has a reference to is the same leak in the other direction.
- **`count ink by ALPHA, and let the assertion return false.** A blank canvas is transparent, so alpha is the only thing distinguishing 「drew nothing」 from 「drew black」. Measured over the 5 layouts × 4 sample sizes with REAL sprites, min ink per lane ranged **24,573 → 110,893** — but read that as a FLOOR, not a bound: sprites are mid-lerp on every frame, so one lane's ink moves a few percent between samples and only a reading near zero means anything. **§3.G4's checker prints a HIGHER figure against its own 71-byte stub** and says so; these are the real-sprite numbers.
- **The lane layout is `data-lanes` on the container, and it is spelled out rather than derived** — 2 lanes `repeat(2,1fr)`, 3 `repeat(3,1fr)`, 4 `repeat(2,1fr)` (2×2, *not* 3+1), 5 a six-column grid with `span 2` / `span 3`, 6 `repeat(3,1fr)`. `cols = count <= 3 ? count : 3` is the formula that looks right and gives four lanes an empty cell. Five's `span 3` on its last two lanes is **positional**, which is why `buildRace()` **appends** `.al-result` instead of prepending it: a leading sibling shifts every `:nth-child` by one.
- **`align-content: stretch` is load-bearing, not cosmetic.** A `center`ed row track is sized to its *content*, so each lane is exactly as tall as its head + canvas + stats, the canvas has no free space to grow into, and `flex: 1 1 auto` on it is a **no-op**. Measured with `center`: two lanes at n=1,025 gave 483×302 canvases and 9.5px sprites inside a 723px stage. With `stretch` the same box gives 483×655.
- **`finishRace()` re-measures AFTER it writes the panel, not after unhiding it.** Unhiding an empty `<p>` gives it one line; filling it with a heading, six list items and a paragraph makes it several times taller, and the lane rows are `1fr`, so every canvas shrinks again. Measuring between the two left `lane.cfg` describing a box the reader is no longer looking at — the reported sprite size was 11.3px where the displayed box gives 14.8px. The ≤1px gap that remains between the CSS box and the backing store is `Math.floor` on a fractional `getBoundingClientRect()`, the same residual the main canvas has always had.
- **Sample sizes are 100 / 250 / 500 / 1,025 and 1,025 is offered deliberately even though it is a colour gradient at five lanes** (measured 7.9px). A hidden rule — 「1025 只在兩條賽道時出現」 — is worse than a visible trade-off the reader chose, so the four are always all there and `finishRace()` *states* the measured sprite size and which of three bands it falls in. The old sizes (60/130/260) were **replaced**, so an old `?n=130` share link lands on the default; that was a deliberate choice, not an oversight.
- **`maxLoggedEvents: 0` on every lane, because a race lane is the only `SortRun` on this site that never rewinds.** The log plus its every-300-events `arr.slice()` costs **~33 MB per lane at n=1,025** — six of which is **~200 MB that nothing would read** — and at n=500 it is ~13 MB per lane, ~77 MB across six, never freed because 500 does not reach the cap. Measured heap across a full six-lane 1,025 race: **flat at 25 MB**.
- **A race lane's cost is DESTINATION AREA, not sprite count.** Measured in headless Chrome at 1,025 sprites/frame over equal painted area: one lane @22px 16.4 ms, six @6px 18.6 ms, six @12px 23.3 ms, six @24px 35.6 ms. Six 311×289 lanes total 539k px — **less than the 735k px single-mode canvas this page already runs at 60fps** — so lane count is not a pixels question and never needed to be capped for one.

### G4. The Sorting Page Finally Has a Checker — and Why It Took One to Write

`sort` is the newest group, and it exists mostly because §3.G3's defect shipped through a 41-script suite: `rg -l "al-lanes"` returned only `sorting.html` and `algo.css`, and `rg -l "sort-run" scripts/` returned nothing. No checker read the page's DOM or its stylesheet, so six permanently blank canvases were invisible to everything the manifest covered.

`check_sorting_page.mjs` (66 checks) is split in two, and the split is the design:

- **STATIC**, 31 checks, ~0.2 s. Reads `sorting.html` / `algo.css` / `sort-run.js` / `shared.js` off disk. A stylesheet contract can be checked by reading it, and mutation-testable from a scratch tree.
- **RENDERED**, 35 checks, ~12 s. Drives the real page over CDP and counts **ink by alpha**. A blank canvas is transparent, so alpha is the only thing that distinguishes 「drew nothing」 from 「drew black」.

**THE RENDERED HALF ANSWERS EVERY SPRITE WITH A 71-BYTE STUB, and that is a deliberate trade, not an optimisation to be proud of.** The page boots by fetching 1,025 sprites at 126.7 KB mean — **~130 MB and 1,025 PNG decodes per navigation**, which was 85% of this checker's runtime and, through the mutation suite's full baseline, most of the suite's. `Fetch.enable` + `Fetch.fulfillRequest` answers the lot with one 4×4 opaque PNG, and the single-mode half now clicks the 單一 tab instead of navigating, because the boot sequence runs `resetSingle()` unconditionally and both modes exist from the first paint.

- **What the stub still catches:** everything §3.G3 is about. Sprites painted into a hidden canvas give zero ink whichever sprite they are, so the original defect is caught in full. So are the five lane shapes, the four sizes, the finish path, and the memory claim.
- **What it gives up:** that the sprite **paths resolve and the PNGs decode**. `PokemonNode.draw()` skips an image whose `naturalWidth` is 0, so a wrong `filename` or a 404 would still produce ink. That class of defect is now uncovered here.
- **The PNG is BUILT, not pasted.** A corrupt stub leaves every lane blank and the checker fails for a reason that has nothing to do with the page, so the chunk/CRC32 constructor runs at import and **re-parses its own output** (`assertWellFormedPng`) — a bad signature or CRC is a startup throw, not 35 red checks. It is **opaque** for the same reason inverted: a transparent stub would make the ink check report zero *for the right reason and fail for the wrong one*.
- **THE STUB IS PROVEN LIVE, OR THE SPEEDUP IS A CLAIM NOTHING CHECKS.** A typo in the glob falls through to real sprites, all 35 rendered checks still pass, and the run quietly takes four times as long — the same shape as a silent skip-cache hit. So the intercepted-request count is asserted `>= 1,025` and printed, and the glob is **read out of `ASSETS.images` in `shared.js`** rather than written down, so the only thing that can desynchronise them is the page moving its sprites, and a static check says so with the cause in the message.
- **Its ink figures are HIGHER than the real ones and not comparable.** An opaque stub fills its destination box; a real sprite covers ~60-70% of it after transparent padding. §3.G3's `24,573 → 110,893` is the real-sprite measurement and stays as the historical figure; the checker prints its own number with that caveat attached.

**THE FAST LOOP IS `--static` ON THE HARNESS, AND ITS PLACEMENT IS THE POINT.**

```bash
node scripts/test_check_sorting_page.mjs --static   # 0.5s — the 31 static checks
```

Two rules keep it honest. It is **not a flag on the checker** — §4 rules out a supported way to skip a check, because a cheap path becomes the path a reader reaches for by default; `check_sorting_page.mjs` has no such flag and never will. And it sits **above the harness's two baselines**, which is not a detail: it was originally below them, so pressing it still ran the browser baseline and all 25 mutation cases first — **the fast loop took longer than the thing it was a shortcut for**, discovered by a reader asking why it was slow. A slow escape hatch is not an escape hatch.

**THE STRIP IS GUARDED BY A CHECK COUNT, not by "it still passes".** The harness copies the checker, deletes everything between the `RENDERED HALF` sentinels, and requires the stripped copy to pass having dropped **exactly 35** checks (66 → 31). That number is **hardcoded, and updating it is the point** — a strip one check too wide would leave every cheap case asserting against a silently narrower checker, and they would all still pass because they only require their own detector, which a narrower checker satisfies more easily, not less. Deriving the expected number from the source would be tautological, so adding a check forces whoever added it to look at where the sentinels are, which is exactly when a misplaced sentinel would otherwise go unnoticed.

**`manual: true` ON THE HARNESS FOR A NEW REASON.** The existing manual entries (`check_gen1_page.mjs`, `check_cries_browser.mjs`) are manual because they open **no repo file**. This one opens plenty — it copies five files into a temp tree — but every read happens in a **child process over a tree outside ROOT**, and `record-inputs.cjs` ignores anything outside ROOT. Inheriting the `-r` preload would not help: the paths opened are the temp copies. So the list is hand-maintained and the flag says so with that reason attached rather than a generic one.

**25 CASES, AND TWO OF THEM WERE WRONG ON THE FIRST WRITE** — the §4 table's rule arriving from a new direction:

- *"a sweep() caller stops clearing its own timestamp"* declared `every sweep() call site passes its context explicitly`, and **passed for an unrelated reason**: the mutation kept `lane.ctx` as the first argument, so that assertion was satisfied. It needed a **new** assertion rather than a re-pointed `expect`, because clearing the timestamp was never guarded at all. Both callers are now asserted on the whole `if (!sweep(...)) <field> = 0;` statement.
- *"a quoted step count is edited"* proved `docblock.includes('524,800')` is the wrong test **verbatim**: `524,800` also appears in the next paragraph, so editing the quote to `480,000` left the check green. Presence is not attribution. The assertion now requires the number to sit within 60 characters of the row's **anchor** wording, against a whitespace-collapsed copy so rewrapping does not break it. `claim` and `anchor` are separate fields on purpose — collapsing them forces the claim to be phrased exactly as the comment happens to phrase it, so a harmless reword breaks a check that was verifying something real.

**AND ONE MORE HARNESS-LEVEL DEFECT, worth naming because the shape recurs:** a nested backtick inside a template literal (a detail message quoting `` `if (!sweep(...)) <field> = 0;` ``) is a **syntax error**, and it made all 26 cases report *"failed, but not on the assertion it claims"* with **empty output**. That reads as 26 mislabelled detectors rather than one broken file. The suite now distinguishes them mechanically: a case whose output contains no `FAIL` at all is reported as **"the checker produced NO assertion, so this case measured nothing"**, which is §4's loader-error rule turned into a harness check instead of a thing to remember.

**ONE PAGE LOAD, THEN THE READER'S OWN CONTROLS.** Navigating per case costs ~25 s because the page re-fetches 1,025 sprites; a first pass at this took half an hour across eight navigations, two fixed `sleep(9000)` waits, and a readiness poll that **matched the previous document** — producing a five-lane case that reported a lane of **zero ink**, which read as a rendering bug and was the harness measuring the wrong document. It now loads **once** and drives the algorithm chips and the sample-size select with `click()` and a `change` event, which is both faster and a better test: a control whose handler never fires is invisible to a URL-driven check.

**`Network.setCacheDisabled` IS NOT WHAT KEEPS THE RUN FRESH, and the source no longer says it is.** One run reported the old `.al-lanes` rule and the first explanation was a stale HTTP cache. It was not: a **concurrent session had reverted `algo.css` on disk**, and the run went green the moment the edit was re-applied. Believing the flag was the safeguard means believing the page is being tested current when nothing was checking it. It stays on — an edit made *during* a run is then picked up — and with the sprite stub the refetch it forces costs nothing.

**THE BROWSER HALF IS FLAKY AT `n=1025`, AND THE INK ASSERTION IS WHY THAT IS WORTH WRITING DOWN.** Measured 2026-10-07: `node scripts/test_check_sorting_page.mjs` fails **1 run in 3** at HEAD, and the failure is a `TypeError: Cannot read properties of undefined (reading 'click')` on the size select, thrown two steps after this line printed:

```
ok   six lanes at n=1025 all have ink (min ∞ px)
```

**`min ∞ px` is the whole bug, and it PASSES.** The minimum is seeded at `Infinity` and reduced with `Math.min` per lane, so a rebuild that has not finished — or a query that matched no lane — leaves it at `Infinity`, and `Infinity > floor` is true. The assertion therefore certified a measurement that was never taken, which is the shape §3.G3 keeps returning to: **an assertion that can be satisfied by having measured nothing**. It is invisible in every green run because `∞` is only printed when it happens, and when it does happen the next line throws, so the crash is what gets noticed rather than the vacancy. Two separate fixes, neither made yet: seed the minimum from a real lane count (`Number.MAX_SAFE_INTEGER` is the same defect wearing a less obvious face), and gate the following click on the select actually existing rather than on a wait. Expect this shape wherever an accumulator's identity element is also the value a `>` comparison passes on.

```bash
# The everyday loop while editing anything the static half guards (0.5s)
node scripts/test_check_sorting_page.mjs --static

# Confirm the browser half (66 checks, ~12s — needs :5500)
node scripts/check_sorting_page.mjs

# The whole group, with the harness (~31s)
node scripts/check_all.mjs --only=sort

# Everything EXCEPT it, while working on anything else
node scripts/check_all.mjs --skip=sort
```

**`--skip=sort` IS THE WRONG ADVICE NOW, and saying so is the point.** It was the fifth-largest group at 190 s; the sprite stub and the tab-click brought it to **~31 s** (14 s + 17 s), which is cheaper than every other CDP group in the suite. The filter to reach for is `--static` at 0.5 s, and `--skip=sort` is only worth knowing in case something else you are running needs the machine.

### G5. The Cry Suite Was Slow For Three Unrelated Reasons, And Only One Of Them Was A Payload

§3.G4 cut the sorting checker from 93 s to 14 s with a **stub**: 130 MB of sprites over HTTP, answered with one 71-byte PNG. The obvious next move was to stub the cry suite the same way, and it is the wrong move for two of its three cost centres, so the measurement came before the edit.

Measured across all 18 cry entries, ~143 s total, and sorted by what the time was actually spent on:

| cost centre | was | is | what it was |
| :--- | ---: | ---: | :--- |
| `test_check_gen1_apu` | 54.4 s | 54.4 s | **CPU.** 17 cases × 151 species × 1,048,576 Hz |
| `test_check_cry_index` | 22.6 s | 6.1 s | **A payload** — 31 MB copied 22 times |
| `check_cries_browser` | 18.6 s | 2.3 s | **Fixed `setTimeout`** — 15.8 s of it, 85% |
| `check_spectrum_browser` | 14.6 s | 4.1 s | Fixed waits, 94% of the file |
| `check_gen1_page` | 9.3 s | 4.5 s | Fixed waits, 64% of the file |

**THE STUB FITS EXACTLY ONE CELL, AND `cry_index` DID NOT EVEN NEED IT.** The three CDP checkers fetch a handful of 16.8 KB files — stubbing those would gut what they measure (real decode → real spectrogram) and buy nothing, because they were never waiting on the network. What they were doing was `await new Promise(r=>setTimeout(r,N))`: 35.5 s of the 42.6 s they took was sleeping. And `test_check_gen1_apu` has no payload at all.

So the one real payload — 682 MB of write traffic to re-derive 22 copies of bytes nobody had edited — is fixed **without faking anything**. `test_check_cry_index.mjs` builds its working tree once and each case restores what it touched. The corpus is still the real 31 MB, the checker still magic-sniffs all 1,674 roster files, and the baseline still has to pass on the tree the cases run against.

**THE TRAP THIS SHAPE INVITES IS A HAND-MAINTAINED LIST OF "PATHS A CASE MAY TOUCH"**, and that is a second copy of the truth: a case grows a new mutation, forgets the list, and the *next* case runs against a dirty tree and passes for the wrong reason. So there is no list — `io.copy` / `io.write` / `io.remove` is the only handle a case has on the corpus and each records its own path. Create, overwrite and delete all restore through one code path, because a path absent from ROOT is removed rather than copied. **Disabling the restore makes cases fail** (`got: [808,809] want: [25,808,809]`), which is what proves it is load-bearing rather than decorative. Hardlinks and symlinks are both refused, and for the reason §3.F already records: `copyFileSync` opens its destination `O_TRUNC`, so a link is as destructive here as a symlink would be.

**A FIXED SLEEP IS A GUESS, AND A GUESS FAILS IN BOTH DIRECTIONS** — too long and every run pays for the worst case on the machine, too short and the next assertion fails spuriously under load and gets filed as a flake nobody investigates. Every ceiling used here exceeds the sleep it replaced, so tolerance only goes UP, and a timeout returns `false` so the assertion still runs and still reports its real number. There is no flag that skips a check, which is §4's rule.

**A WAIT AND A SAMPLING INTERVAL LOOK IDENTICAL IN THE SOURCE AND MEAN OPPOSITE THINGS.** The 130 ms between two `getImageData` calls in the live-curve check, and the 130 ms between two playhead reads in `check_gen1_page.mjs`, are the *measurement window* of a "did this canvas MOVE" assertion — polling for the movement would make the assertion vacuous, so those stay. Conversely the 2200 ms "let it play, then stop it" interval in `check_spectrum_browser.mjs` was replaced with 500 ms, not with a poll, and **trying the poll made the file SLOWER: 14.6 s → 17.6 s**, because it waited for a synthesised Charizard to finish rather than for 2200 ms to pass. Waiting longer than the thing you are measuring is not more careful.

**TWO OF THESE EDITS FOUND REAL BUGS, IN OPPOSITE DIRECTIONS, AND BOTH ARE THE POINT.**

- **A poll that fires too early turns a red into a GREEN.** `check_cries_browser.mjs` waited 900 ms before reading the player's output gain. Polling `taps > 0` — the AudioContext *existing* — returned instantly, before the page had read the stored `{muted: true}` off disk, and the live AudioParam was read mid-sequence at **0.145** instead of 0. That check was *failing*, and it went green, from an edit meant only to save time. The fix is to poll for the precondition for *reading a live measurement*: that the value has **stopped changing** (two identical samples a step apart). Deliberately not `inGain.some(v => v > 0)` — waiting for the asserted condition makes the assertion pass by construction. A page asking for 0 settles at 0, so it is polled, measured, and still fails.
- **An assertion that assumes a precondition nobody established can never pass.** `check_spectrum_browser.mjs` clicked the theme toggle, waited 500 ms, then asserted `dataset.theme === 'light'` — assuming the page starts dark. Headless Chrome reports `prefers-color-scheme: light`, the page honours it, so it loads *light*, the click makes it *dark*, and the check failed **for the whole life of the check** while reporting a message about the ramp being theme-independent. The ramp was fine. It now records the theme it started from, waits for it to *differ*, and checks the plot still carries a spectrogram — the direction-free form of the actual claim. Expect this shape whenever a check names an END state and never reads the START state.
- `rAF` **does** fire in this headless setup (`visibilityState: visible`), so two animation frames are a legitimate way to wait for a repaint — worth measuring rather than assuming, since the usual headless answer is that it does not.

**WHAT DID NOT GET FASTER, AND WHY IT CANNOT — SO IT IS NOT IN THE SUITE ANY MORE.** `test_check_gen1_apu.mjs` runs 34 s and cannot be made cheaper. Its 17 heavy cases each render 151 species at the Game Boy's native rate — 146,311,704 samples — and `renderSpeciesCry` is pure in `(cries, sfx, id)`, so there is nothing to cache, share or stub between cases. The only lever is `POOL`, which the harness already measures for itself ("6 workers 44.5 s, 8 workers 38.9 s, 10 workers 38.0 s") and which is **held at 4 on purpose, because other work shares this machine**. Reducing the number of full-corpus cases instead would mean a case whose `expect` no longer names the assertion that catches its own mutation, which §4 forbids outright. So the entry was **removed rather than flagged** — §4 has no `--quick` on any checker, and a supported way to skip a check is how it stops happening. The file is untouched and still runs by hand.

**WHAT THAT GIVES UP IS NAMED, NOT GLOSSED.** `check_gen1_apu.mjs` is still an entry, so the synthesis is still compared against the reference synthesiser's own output every run. That is the claim about the APU. This harness is the claim about the CHECKER — that each of those 92 assertions would fail if the thing it polices stopped being true — and **nothing else substitutes for it.** A green default run is not evidence that these 39 cases would still catch anything.

**THE REPLACEMENT IS A FOUR-ROW AUDIT IN THE RUNNER, and it is weak on purpose.** `check_all.mjs` reads the retired harness and fails if any of its 39 `expect` strings no longer names an assertion the checker contains. It cannot tell whether an assertion is still MEANINGFUL, only that the harness is still pointed at something real, and one limit is measured rather than implied: **three expectations (`byte-identical`, `Rhyhon`, `0.071`) are each satisfied by more than one assertion's text**, and there are no FAIL lines here to disambiguate them the way the harness's own `caughtBy` does. Its non-vacuity is an **identity between two independent parses of the harness** — the number of cases named and the number carrying an `expect:` — because `eq(orphans, [])` over a regex that matches `expect:` passes on ZERO expectations and prints `all 0 of the retired harness's expectations`. That is §3.B2's vacuous-pass shape, and a floor would have repeated it the day the roster shrank. All five real failure modes were verified against a scratch tree: renaming `expect:`, renaming `name:`, deleting the harness, drifting its header count, editing an assertion description.

**IT LIVES IN THE RUNER BECAUSE A GUARD THAT READS THE FILE UNDER TEST RUNS IN EVERY FIXTURE TOO.** It was first written inside `check_gen1_apu.mjs`, which broke the harness: 22 of the 39 cases run a tree whose checker has had `stripConformance` applied, so the guard read a stripped source, could not find the assertions 17 expectations name, and emitted 17 failures into the one assertion that exists to make stripping safe. A fixture is not the file; the runner is not a fixture.

**THE CASE COUNT HAD DRIFTED, AND THE POLARITY WITH IT.** The harness header said "17 of the 34 cases below assert something that loop never touches. Those 17 are the reason `stripConformance` exists" — but `CONFORMANCE_EXPECTS` is what decides it, and the **17 are the cases that KEEP the loop**; the 22 are the ones that lose it. The count was also stale (34, then 36 in AGENTS.md and `check_all.mjs`) against an actual **39 = 17 + 22**. Read the old sentence as written and it points at removing the wrong half. **The sum is the tell and it went unread twice**: 21 + 17 = 38 was not 39, and the same paragraph then carried 89, 91 and 92 checks at once, each right about a different thing.

### G6. State Shared Through Storage Is Not State a Per-Page Test Can See

**A page's own default was silently muting three other pages, and NO test could see it, because the bug needed a VISIT ORDER.** `sorting.html` starts with its cry switch off, which is correct — it is the only page that can fire a sound every few milliseconds. It expressed that as `cryPlayer.muted = true`, and that setter **persists** (`#save()` writes the site-wide `pokemon-algorithm:cry-volume` key), so merely *loading* the page wrote `{muted: true}` and `cries.html`, `detail.html` and `spectrum.html` then read it back and went permanently silent — with no control of their own to undo it, because `rg -l "cryPlayer.muted" *.html` named **one file, and it was not one of them**. `cries-gen1.html` was unaffected throughout, because it builds its own `AudioContext` and keeps its mute in per-lane memory that is never written anywhere — which is exactly why the report read as two unrelated bugs ("cries and spectrum are silent, but the Gen I lab is fine").

**Why nothing in a 43-entry suite saw it: every checker runs on a fresh `--user-data-dir`, so `localStorage` starts EMPTY on every run.** The defect requires that a page which writes the key be *visited before* a page that reads it, and no per-page checker can express a sequence. This is a distinct entry in §4's list of ways a green run can be wrong, and it is not fixed by asserting anything louder about any one page — the assertion has to be **cross-page in one profile**, which is why `check_cries_browser.mjs` now navigates to `sorting.html` before it asks whether `cries.html` can make a sound at all.

**THE FIRST FIX CLOSED ONE GATE AND LEFT A WORSE ONE, and the shape is the point.** `muteForView()` — apply the mute, skip `#save()` — closes the load path. But `#save()` is also reached from the **volume setter**, and it serialised the *effective* mute, so the page's default rode out through a slider the reader was using for an unrelated reason. Measured, in order:

```
load sorting.html       → key null
drag the volume slider  → {"volume":0.55,"muted":true}
open cries.html         → silent, and no control on that page to undo it
```

A page default that reaches storage through an unrelated control is **worse** than one written on load, because it presents as the reader's own doing. So the mute is two fields: `#storedMuted` is the reader's choice and the only one written; `#viewMuted` is a page's default and lives in memory. **One field cannot carry both decisions because `#save()` cannot tell them apart** — that is the whole reason, and it is a data-model problem rather than a missing `if`.

**`#applyGain()` AND `get muted()` MUST BOTH READ THE OR, and each wrong answer fails silently in a direction the reader cannot undo.** `#storedMuted` alone makes `sorting.html` **loud by default**, contradicting the very intent its own comment records; `#viewMuted` alone ignores an explicit un-mute and leaves `cries.html` silent forever for someone who turned sound on. Neither throws. `sorting.html`'s single reader of the flag (`if (cryPlayer.muted) return`) needed no change, which is the only reason this stayed a two-line edit.

**A WAIT FOR NAVIGATION OVER CDP MUST BE GATED ON SOMETHING ONLY THE DESTINATION HAS.** The cross-page wait was gated on `nav[data-nav] a` — which **the page being navigated away from** also has, so `booted()` returned instantly against the old document and the next line threw `TypeError: Cannot set properties of null` on a page that was not the one being read. `Page.navigate` resolves when the navigation is committed *to the browser*, not when `Runtime.evaluate` reaches the new document, and the two documents share an origin — so **anything they have in common is evidence of nothing**. It waits on `#audioVolume`, which only `sorting.html` has.

**THE FIX IS PROVED BY MUTATION IN BOTH DIRECTIONS, and the second direction is the one that matters.** Reverting `sorting.html` to `cryPlayer.muted = true` fails three checks; making `#save()` write `#storedMuted || #viewMuted` again fails the same three. A negative case that only undoes the load path would leave the slider path unguarded, so the slider is now **exercised deliberately** in the cross-page section — nothing touched it before, which means the second gate had no test at all. Its wait is on `volume === 0.55`, the *other half of the same write*, so it proves the write **happened** rather than proving that nothing ran; polling for the absence being asserted would pass instantly on a page that never wrote at all.

**THE MEASUREMENT HAS TO DISTINGUISH "MUTED BY THE CHECKER" FROM "SILENT".** The tap zeroes `ctx.destination`, so `TAP_PROBE`'s own `gain` is 0 by construction. The player's level is read from `inGain` — one node upstream, the player's own gain — so "the checker muted the last centimetre" and "the page asked for nothing" are separate numbers rather than one. Expect this shape anywhere a test silences the thing under test: **discard the output, measure upstream of it.**

### H. Category Pages vs. `types.html` — Two Different Questions

`category.html?cat=dragon` and `types.html?type=dragon` both exist and both list the same 70 species. **A category page must never link to `types.html`, and must never be merged into it.** Decided by the user when the Dragon page was added; do not re-propose the cross-link.

- A **category page** answers 「有哪些龍屬性寶可夢」 — a roster plus an introduction. Its `prose` and `notes` are this project's own zh-Hant editorial, which is the point: it is the detailed species introduction.
- **`types.html`** answers 「龍屬性的招式、特性、道具、訓練家與相剋關係」 — battle mechanics, and the only place the effectiveness matrix appears. Its prose is upstream English by design (§3.D), so it is not a substitute for a zh-Hant introduction and must not be given one.
- The two are complementary, not overlapping, so a reader who needs the mechanics follows the site's own type browser from the nav. Adding a "see also types.html" link to the category template was considered and declined: it would put a battle-mechanics page on the path of someone who asked a species question.

**Adding a category is a three-list edit, in this order.** `CATEGORIES` (append the config), `CATEGORY_SLUGS` (append the slug — it is a literal list, *not* `Object.keys(CATEGORIES)`, and `category.html` falls back to element `[0]` on an unknown slug, so never insert at the front), and `NON_HUB_SLUGS` or `COLLECTION_GROUPS`. All three are literal lists on purpose: `check_categories.mjs` asserts `CATEGORY_SLUGS \ HUB_SLUGS === NON_HUB_SLUGS` and hub order against `CATEGORY_SLUGS.filter(...)` with `===` on the exact array, so a category that reaches the hub by omission is impossible by construction. Appending is the only insertion that leaves both orders untouched.

- `totalCards === 11` in `check_categories.mjs` is a hardcoded count of the hub. Prefer `NON_HUB_SLUGS` (the 600族 and 龍屬性 precedent): the homepage already links both from the 熱門搜尋 row, and the collections hub is a different navigation surface that neither page needs to appear in.

### I. The Page/Module Boundary Had A Shipped Defect, And Nothing Could See It

`sorting.html` called `cryPlayer.muteForView(true)` from commit `e1eb879`. `assets/js/cry-player.js` did not define that method until `8957cc0`. For the commits in between, every load of sorting.html threw `TypeError: cryPlayer.muteForView is not a function` — and because that call sits about six lines ABOVE the listeners for the mute checkbox, the volume slider, the legacy checkbox and every keyboard shortcut, the throw took all of them with it. The page rendered, the header rendered, the race ran, and the controls were dead.

**ESM statically verifies the IMPORTED BINDING and says nothing about the member**, so the import was legal, the module loaded, and the defect was a runtime TypeError on a line no checker read. `check_sorting_page.mjs` has 66 checks over that page and none of them see it, because all of them are about the DOM and the stylesheet. `check_nav_pages.mjs` asserts the nav *call* exists in source, not that the script reached it.

`scripts/check_page_module_api.mjs` is the guard: for every page, every `X.member` reached through a named import must exist in the module `X` was imported from. 295 bindings across 17 pages, 0.1 s. The page set is derived from "imports from assets/js" rather than an exclusion list, so a new page is covered the moment it exists and `404.html` needs no exception; `pageCount > 0` is asserted so an empty derivation cannot pass as "0 violations".

**Three things about writing it that are worth more than the checker.**

- **THE PAGE SET HAD TO BE SELF-SELECTING.** The first version derived pages from the directory with an exclusion list, which is `check_nav_pages.mjs`'s problem — and that file then asserts each exclusion still works, because an exclusion list is a place a regression can hide. Deriving from the import predicate removes the list instead of defending it.
- **A COMMENT IS A FALSE POSITIVE.** sorting.html:964 is prose reading "`cryPlayer.muted` reads and WRITES the site-wide `cry-volume` key", so scanning raw source reads members out of sentences about them. Comments and string literals are masked, and template `${…}` holes are kept because those are code.
- **`GbApu` ASSIGNS NINETEEN PUBLIC INSTANCE PROPERTIES IN ITS CONSTRUCTOR.** A member set built from method syntax alone reports every one of them missing the first time a page reads `apu.notes`, and then the checker is right about nothing. `this.x =` is collected too, and the direction is deliberate: over-approximating turns a red line green, while under-approximating produces noise a reader learns to ignore.

**`export const cryPlayer = new CriesPlayer()` IS AN INSTANCE, NOT A CLASS, AND THAT NEARLY SHIPPED THE CHECKER BLIND.** Resolving members from class exports alone returns nothing for the one binding this checker was written for, so `used` was empty for all 295 bindings and the assertion printed PASS having measured nothing. Both self-checks were happy, because they test the member SET and never touch the pattern. `check_page_module_api.mjs` therefore asserts separately that an exported INSTANCE resolves to its class members — the assertion whose absence let the bug through.

**THE ESCAPE WAS WRONG IN A WAY ONLY A MUTATION COULD FIND.** The member pattern was written `(?:\?\.)`, meaning an optional literal `?` then a literal `.`; it is actually a literal `?` followed by a literal `.`, so it demanded the two-character sequence `?.`, which no ordinary member access contains. Nothing matched, nothing was compared, and the run was green. `\?` is an ESCAPED LITERAL, not a quantifier — the quantifier is a second `?`. Reading it does not surface that; renaming a method and watching the checker stay green does. The same mistake also hid a generator export (`export function* bfsSolve`), which the checker reported as three missing exports from maze.html before the pattern was corrected.

**Verified by mutation, in both directions, on two different modules:** renaming `muteForView` reports `sorting.html: cryPlayer.muteForView — cryPlayer (assets/js/cry-player.js) has no "muteForView"`, and renaming `astarSolve` reports the missing export from `maze.html` with the module's real export list attached. Neither is visible anywhere else in the suite.

### J. Every CDP Checker Leaked A Chrome Profile, And 28 GB of tmpdir Proved It

Three of the six browser checkers removed their `--user-data-dir`; three did not, and nothing reported it. `tmpdir` held **3,229 entries and 28 GB**, of which 291 were Chrome profiles — 135 `cr-`, 72 `cdp-`, 43 `spx-`, 36 `sortpage-`, 5 `of-` — and the prefixes belonging to the two checkers that DID clean up were the small ones. This is the same disease AGENTS.md records for five orphaned `http.server` processes, in a directory nobody had looked at.

Cleanup is a `process.on('exit')` handler rather than a line at the bottom, because the bottom does not run when a check throws — and a throw is exactly when the run is already going wrong. It does run for `process.exit()`, which both of these files use, so the common path and the throw path are covered and only SIGKILL leaks. Verified by counting: 135 `cr-` and 43 `spx-*` before and after a real run of each, unchanged.

**The mutation harnesses leak the same way, and there are 431 more of them** — `colormatch-neg-` 105, `cp-negtest-` 96, `criespage-neg-` 87, `cry1-neg-` 64, `cryfeat-neg-` 61, `gen1apu-neg-` 18. Those are left alone here because they are per-case trees inside a harness that already owns its own lifecycle, and cleaning them is a separate change from stopping a leak.

**The 727 existing directories were removed**, scoped to those eleven prefixes rather than to tmpdir as a whole — which held 3,263 entries and is now 2,536, because everything else in there belongs to other applications. Reclaimed **13 GB, 29 G to 16 G**. Before deleting, `ps` was checked for a live `--user-data-dir` on any of the eleven prefixes: deleting a profile out from under a running checker would break it, and the run in flight at that moment belonged to port 9557, which is not one of this repo's.

## 4. Verification & Testing Commands

Run regression checks whenever modifying data structures, selectors, or color logic.

**`node scripts/check_all.mjs` runs everything, and skips whatever cannot have changed.** The suite is 43 scripts run by hand and they are not equally expensive: `check_gen1_apu.mjs` is 6.0 s of which 5.0 s is one pass over the 151-species corpus at 1,048,576 Hz (146,311,704 samples). **Measured on this machine: 96 s of checker time cold, 0.0s when nothing relevant moved.** A fourth of that used to be `test_check_gen1_apu.mjs` alone (37 s, 17 of its 39 cases needing that same pass), which §3.G5 explains cannot be made cheaper and which is therefore no longer an entry. The four spectrum scripts add ~9 s cold, and two of them (`check_spectrogram_port.mjs` and its mutation suite) need the venv, so a machine without it skips those with the reason printed rather than passing.

- **There is deliberately no `--quick` flag on any checker.** `check_gen1_apu.mjs` already says why: "a supported way to skip the conformance comparison is exactly how it would stop happening." A flag is a promise the reader has to remember to keep. The skip lives in the runner, is derived from file CONTENT, and a skipped checker says so on its own line with the reason.
- **Every manifest entry gets ONE line with a time column, and the column makes three different claims.** `6.0s` is measured this run, `last 6.0s` is a cache hit reporting the previous green run's measured duration (stored as `${name}~` beside the key and the `@` timestamp), and `-` is a row that never ran — a missing script, or a CDP checker with no server on `:5500`. One `row()` helper emits all of them, because five call sites each padding their own column is five chances for the table to drift; it pads the detail but never truncates it, because an `ok` line must fit 56 columns while a skip naming the Runtime Server rule must keep that sentence whole. Two traps are named in the source: the durations live in a **non-cached region of the output's meaning, not in `budget`** — a cache hit's number is real but was not paid for this run, which is why the legend says so and the summary total still sums only what ran; and the cached value is read with `== null`, because `Number(null)` is `0` and would print `last 0.0s` for every entry written before durations were stored. A `▶` line precedes each run because `execFile` buffers — without it, the 13 s of `test_check_color_match.mjs` is a terminal that looks hung.
- **The input lists are PROVEN, not reviewed.** `--prove-inputs` runs each checker under `scripts/lib/record-inputs.cjs`, a CommonJS preload that records every repo file it opens, and fails if the recording disagrees with the manifest. Miss one file and the checker is skipped after that file changed, so the run is green having verified nothing — strictly worse than no cache, because it looks like coverage. A grep cannot answer it, for the reason `check_nav_pages.mjs` documents about `rg -l initHeaderNav *.html`. Two directions are both required: **read but not declared** (the dangerous one) and **declared but not read** (a typo or a checker that stopped reading something). Proven by breaking the manifest in a scratch copy — both fire.
- **It is a `-r` preload and not `--import`, and the difference is silent.** Node snapshots a builtin's ESM named exports when the module is first linked, so `import { readFileSync } from 'node:fs'` binds the ORIGINAL function and a patch applied by an `--import` module afterwards is never seen. Measured: with `--import`, `check_color_palettes.mjs` recorded five files and missed both JSON tables it plainly reads. A CJS preload runs before the main module is linked, so the same patch is picked up by every named import.
- **What is always in the key, whatever a checker declares:** the checker itself, the checker a negative harness exists to attack, every file in `scripts/lib/`, and `check_all.mjs` itself. Editing a checker therefore invalidates its own entry with nothing extra for a maintainer to remember, and changing the cache's own rules cannot reuse entries the old rules produced.
- **Two checkers are honestly unverifiable and say so on every run.** `check_gen1_page.mjs` and `check_cries_browser.mjs` open NO repo file — their pages arrive over HTTP from Live Server — so their input lists are read off the HTML by hand. That is the weakest claim in the manifest and it is printed as such rather than hidden behind a green tick. The recording is what *establishes* that they touch nothing, rather than a comment claiming it.
- **Also named, because each is a way this can be green and wrong:** a file read only on a branch NOT taken during the recording is not seen (mitigated by the checker's own hash being in the key); existence probes are keyed on `path:size`, not content; files over 256 KB — the cry corpus, the GLBs — are keyed on `path:size:mtime` rather than content; and the cache trusts the last green result on this machine, so `--force` exists for a checker that passed for a reason other than its inputs.
- Groups are `cry-apu`, `cry-data`, `cry-page`, `color`, `nav`, `data`, `type`, `model`. `--skip=cry` covers the first three without naming them; `--only=`, `--force` and `--no-cache` also work. `node scripts/check_all.mjs --help` prints them with each group's last measured cost, so the runner can be asked what it costs rather than read to find out.

### RUN THE CHECK YOUR CHANGE NEEDS, NOT THE SUITE

**There is a mechanism for this and it is `--only=`, and the reason it exists is arithmetic.** A full cold run is 96 s across 43 entries. Of that, **49 s is nine mutation harnesses running one child process at a time**, and 36 s of it is sequential work that has nothing to do with most edits. The skip cache already handles the *second* run — 0.0 s when nothing relevant moved — so what is left unhandled is the first run after an unrelated edit, and the answer to that is not "run less often", it is "run the group that covers the file".

**The mapping below is by WHAT YOU EDITED, not by group, because a group is an implementation detail and a file is what you have in your hand.** Each row is derived from the `inputs` lists in `check_all.mjs`, which is why `--prove-inputs` matters: a missing entry there is a file whose checker would be skipped after that file changed, so the first column is a claim and not a convenience.

| you edited | run this | why this and not that |
| :--- | :--- | :--- |
| `spectrum.html`, `spectrum.css` | `--only=cry-page --only=cry-data` | the spectrum page's claims are split across a CDP checker, a page checker and the port checker |

| `sorting.html`, `algo.css`, `sort-run.js`, `sorting-algorithms.js` | `node scripts/test_check_sorting_page.mjs --static` first, then `--only=sort` | the static half is 31 checks at ~0.5 s and catches the stylesheet contract; the browser half is a real page and costs 10 s |
| `colors*.css`, `color-palette.js`, `color-match.js`, `colors.html` | `--only=color` | 11 entries, and 13 s of it is one harness |

**`--only=cry` IS A PREFIX MATCH, NOT A LIST, and that is why it is the right default.** `inGroup()` tests `group === f || group.startsWith(f + '-')`, so `--only=cry` picks up three groups and `--skip=cry` drops three, without anyone maintaining a fourth list of what "cry" means.

**WHAT NOT TO DO.** There is no `--quick`, and §4's rule says why: a flag that skips a check is a promise, and the promise is what stops being kept. When `test_check_gen1_apu.mjs` had to come out of the suite, it came out by being **removed**, with the file left runnable and the cost of the removal written down — not by a flag. If a check is too slow to run, the two legitimate moves are to make it cheaper (§3.G5's fixture and pool work) or to take it out of the manifest and say what is no longer proven.

**AND WHEN YOU DO NOT KNOW WHICH GROUP OWNS A FILE, ASK.** `node scripts/check_all.mjs --prove-inputs` answers "which checkers read this file" from the recording rather than from a guess, and it is the same recording that keeps the cache honest. A grep cannot: `rg -l initHeaderNav *.html` lists `sorting.html` because its import names the symbol, and two other pages only because they mention it in a comment.

**Know what a group costs before choosing a filter.** Measured from one full cold run, **96.2 s of checker time over 43 entries** — a second run of the same tree measured 88 s, so read the column as a band rather than a constant. The 340.9 s over 41 that preceded it was measured on a machine competing with Chrome at 97% CPU and is kept only as the reason the numbers are not comparable across revisions — **treat the current column as the floor and any figure measured under load as an upper bound**, which is the same caveat the harness's own `POOL` comment carries. The four rows that moved most were re-measured after the work in §3.G5, because leaving old figures next to new code is how a table stops meaning anything:

| group | secs | entries | where its time goes |
| :--- | ---: | ---: | :--- |
| `color` | 32.0 | 11 | `test_check_color_match.mjs` 13 s — 28 cases over 6,148 corpus colours, was 42 s when it ran them one at a time |

| `data` | 0.5 | 4 | `check_learnsets.mjs` 0.2 s |
| `model` | 0.1 | 1 | — |

**No group is a mutation harness any more, and that is the whole change.** Three of them were 62% of the suite, because a negative case is a whole checker run in a temp tree. The two that could be made cheaper were — 42 s to 13 s by running four at a time, 22 s to 3.1 s by building one tree and restoring what a case touched — and the third could not, so it left the manifest instead. **A negative case is only as expensive as the thing it is attacking**, and the honest question when a harness is slow is which of those two it is.

**`sort` is the exception that proves the shape is about the PAGE, not the harness.** Its harness is the same construct as the APU one — a whole checker run per baseline — yet it costs 9.8 s against a corpus-rendering 42 s, because the checker answers 1,025 sprite requests with a 71-byte stub and loads the page once (§3.G4).

## 6. Git Workflow Rules

- **No Push Without Explicit Permission**: Commit freely, but **never run `git push`** — not for a first push, not for a branch, not for a fix, not because CI is red. The remote is only pushed when the user says so in their own words, and a request to commit is not a request to push. When it is unclear whether more work is coming, assume it is and stay local. Check what is pending with `git log --oneline origin/<branch>..HEAD`.
- **Atomic Commits**: Commit at the end of every coherent unit of work (e.g. one bug fix, one component layout, one page enhancement).
- **Batch by direction, not by file**: One commit per *direction of change*, and a direction may legitimately touch several files — a fix plus the test that proves it, a refactor plus the docs that describe it, or one invariant tightened across every checker that enforces it. Splitting those apart produces a history where no commit is independently verifiable, which is the thing atomicity is for. Do not split work that only makes sense together, and do not merge work that could be reverted separately.
- **The line is unrelatedness, not file count.** Lumping genuinely unrelated modifications together is still wrong — a colour-palette fix and a nav fix are two directions even if they land the same afternoon. But "one commit per file" and "one commit per hunk" are both wrong in the other direction: they bury each commit's intent in bookkeeping. When in doubt, ask whether reverting this commit alone would leave the repo coherent; if yes, it is its own commit, and if no, it belonged with whatever it is entangled with.
- **Targeted Staging**: Stage only the specific files touched by the unit (`git add path/to/file`). Never use `git add -A` or `git add .` to avoid capturing untracked scratch files.
- **Meaningful Messages**: State what changed, why, and any specific metrics or design choices involved.
